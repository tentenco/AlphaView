# 保存設定的歷史路徑

方法版本：`alphaview-workflow-path-validation-v1`。保存工作流明細可按「檢查保存設定的歷史路徑」，只讀本機日線，重新選股、配置並計算一條假設路徑。既有單項規則驗證保持獨立；這個功能沒有「通過」結論，也不參與提案或就緒閘。

## 固定來源與歷史時間

使用保存請求的**全部候選代碼**、策略權重、門檻、最大持倉數、單檔上限、現金緩衝、配置方法與波動回看。不是把最後選入的標的往回持有。帳戶允許標的政策若已綁定，也固定使用保存值；先排名、再移除不允許的原席位，不從下名次補位。

候選清單和保存的 RPS 股票池是當下選擇，不是歷史各日的成分股。這個研究有事後選擇與倖存者偏差，即使程式每次只看歷史前綴，也不能稱為當時股票池的策略回測。使用者若在看過結果後修改設定，另有未計入的搜尋偏差；本功能不做最佳化或樣本外檢定。

- 結束日一律來自 `sessions.latest_completed_session()`，固定最新 252 個完成 XNYS 交易日；第一個訊號日是測試開始前一個交易日。
- 每 21 個交易日做一次決策，共 12 次；收盤後訊號在下一交易日未調整開盤價模擬成交。最後一次決策之後繼續逐日估值至結束日。
- 每次將原始本機日線先截到訊號日，再獨立呼叫既有 `research.indicators` 和 `research.evaluate`；不在包含未來資料的指標表上取一列。調整 OHLC 的定義、成交量、Wilder RSI、完整均線暖機與固定訊號規則均沿用選股引擎。
- 每次以保存權重加總共識分數，依分數、符合數、代碼排序，再呼叫既有 `alphaview-allocator-v1`；反波動／分數傾斜的查詢以該訊號日為結束日。缺資料不退回等權、不轉移啟用權重。
- 本機調整價仍是目前的修訂資料，並未重建歷史當時供應商的資料版本；前綴限制不能消除這項偏差。

## RPS 與完整覆蓋

啟用 RPS 時，必須找到該保存工作流引用的 `scans.id`，採用那筆快照完整的 `universe`；不改成只在候選或最後選入標的間排名。至少三檔，每個決策日全部必要同儕都要有有效的 RPS 指標。任何必要同儕缺失，該決策不可用，整條績效不發布。

每次最多 30 檔候選、100 檔必要標的（包含完整 RPS 股票池）；每檔截至結束日最多 3000 筆本機日線。先計數再載入，超限不偷偷截短歷史。每次至多 1200 個獨立指標前綴。新上市、日曆缺口、非有限價格、啟用訊號不足或配置器缺少波動樣本，都保留原因，不刪除該標的後重算組合。

回應包含每個決策的必要／有效候選規則組數、必要／有效 RPS 同儕數，以及整段所需 12 次決策、完整決策數和 252 日估值覆蓋。缺口會使 `status=unavailable`、`metrics=null`，不輸出部分績效曲線或部分成交來冒充完整路徑；`valued_path_sessions=0` 表示沒有發布完整路徑的估值覆蓋。

## 模擬帳務

固定起始現金 100,000，使用可分割的假設股數、單邊 10 bps 費用、零滑價；現金利息為零，期末不強制平倉。不是讀取或重建任何私人帳戶。

每次調倉以當日未調整開盤計算原持倉值，對目標與原持倉的**淨差額**計費。以二分法求費後資產值，使「費後資產＋淨交易費＝費前資產」；保存目標百分比乘上費後資產，再除未調整開盤，得到新股數。費用從現金扣除，沒有槓桿或借款。單檔封頂、空席與小數取位餘額沿用配置器語意，保留現金。

若所有候選的必要訊號完整，但無人符合選入條件，記錄 `hold_no_candidates`，保留原部位與現金；不建立清空指令。這對應原工作流「沒有符合候選就不產生提案」的行為。這和必要訊號缺失的 `unavailable` 明確分開。

每日估值使用假設股數乘**未調整收盤**。若隔夜持有標的的相鄰 `adj_close / close` 因子相對變動超過 `1e-6`，整條路徑回報 `held_corporate_action_unmodeled`，包含標的、日期與兩日因子。未重建股息、拆併股、權利或稅務；不把調整價直接當成帳戶現金或推算公司行動所得。極小於容差的因子變化可能無法識別，公司行動本身也可能未反映在本機資料中。

輸出包含日資產曲線、現金、曝險、每次決策的排名與目標、逐筆淨交易、模擬費用、期末持倉、總報酬與從起始資金起算的最大回撤。沒有基準、Sharpe、PSR、DSR 或勝率結論；不把一條固定設定的歷史路徑解讀為策略驗證通過。

## API 與畫面契約

`POST /api/portfolio-agent/runs/{identifier}/path-validation`，`@store.snapshot_read`、`Cache-Control: no-store`，請求只接受：

```json
{
  "expected_proposal_fingerprint": "64 字元 SHA-256 小寫十六進位",
  "expected_input_revision": "使用畫面讀取的保存版本",
  "expected_as_of": "YYYY-MM-DD"
}
```

工作流必須已保存、為 `proposed`，且保存引擎、輸入版本、交易日與帳戶政策仍當期。來源不符回 409，額外欄位或日期無效回 422。回應帶當次 `as_of`、`input_revision`、各引擎版本、保存提案、設定、原始歷史與完整證據的 SHA-256。沒有 SQLite schema 或寫入；不保存研究紀錄、不修改提案、不觸發供應商、模型或券商。

主畫面掛載 `WorkflowPathValidation`，接受 `run`、`enabled`、`t`；以帳戶識別與工作流來源作 React key。只有明確按鈕才計算。來源回應先核對四個綁定欄位，再重新讀取 run；每 30 秒或回到分頁時重查來源。來源失效、核對失敗或切換工作流／帳戶就停用結果和下載；重複點擊只送一個請求，離開時中止等待。

下載 JSON 保存已通過來源核對的完整伺服器回應文字，沒有額外 API、重算或寫入。畫面解析資料後，下載前會再核對原文字解析後與已接受物件完全相符，並拒絕非有限值或不相符的內容；物件鍵順序不影響核對。原文字的 `1.0`、`-0.0`、指數寫法、空白、未知欄位與 `null` 原樣保留，不再以 `JSON.stringify` 改寫數字，讓離線工具可依後端 canonical JSON 規則重算證據指紋。這只修正檔案表示方式，計算方法 v1 維持。

原文字與結果放在同一接受狀態；來源失效、等待新計算、工作流／帳戶切換或來源重查中，都不能下載舊結果。`current_at_snapshot` 僅表示當次快照有效，不表示離線開啟當下仍新鮮。

## 這不是什麼

不是當時可投資股票池的策略回測、樣本外證據或完整自動化績效。沒有模型決策、市場風險覆蓋、停損／冷卻、帳戶斷路器、流動性限制、整股／最小委託量、拒單與委託生命週期。模擬費用不保證涵蓋實際成本，歷史正報酬不代表未來有效，也不構成交易指示。

實作：`alphaview/panel/workflow_path_validation.py`、`web/src/WorkflowPathValidation.tsx`。後端測試使用隔離 SQLite、合成日線並禁止外部 HTTP；涵蓋實際修改較晚日線後早期決策不變、次日開盤與未調整估值的手算核對、RPS 完整分母、缺啟用輸入、公司行動失效、來源衝突及並行寫入快照。UI 測試涵蓋按需計算、重複點擊、空值／零、來源核對失敗、背景失效、工作流切換與離線下載。
