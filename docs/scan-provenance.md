# 選股快照的引擎與資料版本

選股快照的 `input_revision` 使用下列格式，無須增加 schema：

```text
alphaview-scan-v1|<工作區 identity>:<inputs_revision 計數>
```

唯一版本定義位於 `alphaview/panel/scan_provenance.py` 的 `SCAN_ENGINE_VERSION`。資料計數由持股、日線、dataset metadata、市場成分與市場 metadata 的交易內 trigger 更新；掃描快照及作業進度不改變輸入版本。

掃描開始時保存引擎版本，在同一唯讀快照取得輸入版本、股票池及日線。完成計算後，在 `BEGIN IMMEDIATE` 內核對引擎及資料版本仍相同，才發布整批結果。中途直接寫入資料或引擎版本改變，均不將新版本貼到舊計算結果上，也不留下部分批次。

## API 判讀

- `input_status: current`：引擎及資料版本皆為目前版本。
- `input_status: stale`：可辨識完整版本，但引擎或資料已改變。
- `input_status: unknown`：沒有版本，或只有早期未含引擎的資料 token。不能因資料計數看似相同就假定有效。
- `scan_engine_version` 與 `current_scan_engine_version` 分別列出快照及目前引擎。

個股明細還要求快照日期與檢視的完成交易日一致；資料變更後，歷史日期明細也不把舊訊號和新修訂日線混用。未知／過期訊號保留在原始快照中，明細隔離並提示重算，不刪除歷史紀錄。

每日訊號異動只有兩期皆有完整且相同的 token 才比較策略進出。相同舊引擎及舊資料版本仍可作為歷史快照比較，但明確標示不代表目前輸入；不同引擎或不同資料版本不宣稱策略進出，股票池成分異動仍可單獨列出。

`/api/status` 與 `/api/overview` 的畫面 revision 同時包含選股與回測引擎版本；部署任一引擎更新但資料未寫入時，輪詢客戶端仍能察覺需刷新。回測使用自己的 `BACKTEST_ENGINE_VERSION` 與內容指紋，兩種版本分開維護。

## 何時必須升版

只要修改可能改變選股結果，就升 `SCAN_ENGINE_VERSION`，例如：

- 指標數學、暖機、缺值／非有限值處理。
- 策略門檻、訊號規則及所需資料資格。
- RPS 排名母體、排名算法或有效樣本處理。
- 日期、交易日與未完成行情的選取方式。
- 影響上述行為的依賴升級。

純畫面排版或不影響意思的文字修正不需升版。不可重用已發布版本號。新增規則必須附回歸測試；升版後的舊結果標示需重算，不能偷偷改寫舊快照。部署者應安排重新掃描，完整發布後畫面才恢復 current。

這項變更只改 token 內容，備份資料庫 schema 與既有已登錄 schema 指紋不變。備份可保留舊 token，恢復政策仍須重新檢查版本；備份預檢本身不恢復資料。
