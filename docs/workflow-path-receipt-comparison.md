# 保存路徑回條比較

兩個保存工作流可能在同一份歷史資料上使用不同權重、配置限制或股票政策。此面板讀取兩份不可變回條，並列原始設定、來源脈絡與歷史結果，說明哪些比較基礎相符。它不重新計算路徑，也不把結果差異歸因於某一個設定。

這不是績效排名、優勝者選擇、統計通過判定、目前提案資格、交易授權或交易建議。回條的當期來源狀態是比較當下另外取得的觀察；即使兩筆都已過期，只要保存的比較基礎完整且相同，歷史原值仍可比較。

## 使用方式

選擇帳戶和回條種類後，按「載入此帳戶全部回條」，再選擇不同的基準與對照回條。載入和比較都由使用者觸發；切換帳戶、帳戶版本或種類會清除選擇及舊結果。無法驗證的回條仍出現在清單中，但不能選為比較來源。

差額方向固定為「對照 − 基準」。報酬率與回撤差額使用百分點，不是百分比變動。原值保留在畫面中；缺值或比較基礎不相符時，差額顯示 `—` 並列出原因，不補零、不改算交集期間、不丟棄日期，也不重新設定起始資金。

## 可比較條件

- 保存的回條、證據、路徑、工作流、掃描、配置器版本完整且相同；保存的路徑方法文字也必須相同，避免混用成交與估值方法。
- 原始歷史資料指紋完整且相同；候選清單和 RPS 股票池逐項相同，無重複標的。
- 完整期間的 signal_start、start、end、sessions 相同。逐日估值日期必須有效、嚴格遞增、無重複，而且兩份完整日期序列完全相同。
- 原路徑狀態為 evaluated，決策與估值涵蓋完整，曲線值和必要指標皆為有限值。
- 保存的起始資金為正、與原指標一致且兩側相同；基準費用與滑價假設相同。

工作流設定、symbol policy、再平衡週期可不同；差異會明列，並不自動使結果不可比較。不同 input revision 也不單獨禁止歷史比較：真正比較的是保存的原始資料指紋與完整基礎，來源脈絡差異另行顯示。

必要指標包括 initial_cash、final_value、return_pct、max_drawdown_pct、total_fees、traded_notional、trade_count。缺少任何必要值時不產生該比較的量化差額；非有限差額也不回傳替代數字。

成本情境只配對完全相同的 fee_bps / slippage_bps。各組必須符合保存請求且不得重複；重複或無效成本組合使該份比較無法量化。每組配對另外核對情境狀態、完整日期、起始資金與有限指標/明列成本。未配對、缺值或不可用的情境保留原因與 null 差額，不採最近的費率、不內插。

## API

`GET /api/paper/accounts/{account_id}/workflow-path-receipts`

跨工作流的帳戶回條索引。可指定 kind=path_validation 或 path_costs；limit 預設 20、上限 50，offset 上限 250。回傳可驗證性、讀取當下的 currentness 與分頁資訊，不含完整原件。帳戶必須存在。

`POST /api/paper/accounts/{account_id}/workflow-path-receipts/compare`

只接受 baseline_receipt_id、selected_receipt_id、expected_baseline_fingerprint、expected_selected_fingerprint 四個欄位。兩個 ID 必須不同、屬於同帳戶且同種類。不同工作流可比較。內容指紋改變或回條無法驗證回 409，跨帳戶或找不到回條回 404，種類/欄位/界線不符回 422。

回應包含完整 baseline.original_receipt、selected.original_receipt、各自來源狀態觀察，以及 comparison。所有端點使用 `@store.snapshot_read`；不寫任何資料表，不增加 schema。歷史比較不呼叫路徑計算、資料供應商、模型或券商。

完整回應使用有限、排序鍵的 UTF-8 JSON，大小上限 5 MiB；超限明確拒絕，不截短。前端保留已接受回應的原始文字，下載按鈕直接以相同文字建立檔案，不發送第二次請求，也不重算比較。因此下載中的 currentness 是原比較當下的觀察，不宣稱為下載時的最新狀態。

## 驗證範圍

合成測試涵蓋不同工作流設定、精確量化方向、未重算原件、query-only 快照、方法/資料/日期/指標不一致、重複日期、過期來源與歷史可比較性分離、帳戶範圍、指紋變更、損壞原件、匯出大小上限、成本組合精確配對與重複拒絕。

前端測試涵蓋手動載入、空選擇、重複選擇、連點去重、不可驗證回條、缺值顯示、原文下載、跨帳戶延遲回應隔離、409 與超限回應。正式掛載、整體五道關卡與 390px 瀏覽器檢查由主代理完成。
