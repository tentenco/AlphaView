# 保存路徑回撤與恢復

`alphaview-workflow-path-drawdowns-v1` 從同一帳戶的一筆不可變 `path_validation` 回條，描述保存淨值的回撤深度、谷底與恢復時間。使用者先載入最多 50 筆回條、選一筆可驗證原件，再手動檢視。這不是恢復預測、風險排名、統計通過判定、交易建議、執行來源或就緒閘；沒有帳本、持股、回條、工作流、外部資料、模型或券商寫入。

## 原件與資料基礎

只使用完整原回條，沿用保存回條比較的嚴格 self-basis：方法版本、歷史資料指紋、候選與 RPS 股票池、完整日期與涵蓋、起始現金與基準成本、必要有限指標。再以原件 `signal_start` 至原件 `as_of` 的 XNYS 歷史交易日曆，核對 252 個估值日及其前一個訊號日。檢視時的最新交易日只記錄來源現況，不用來改變保存期間，也不讀目前 bars 或重新運行路徑。

任一缺值、非有限值、非正淨值、重複日期、亂序、缺日、歷史交易日曆不符或必要基礎不完整，整份回撤分析為 `unavailable`；`episodes`、`curve`、`summary` 均為 `null`，UI 顯示 `—`。不丟棄、排序、插值或補零。完整原件及原因仍保留供下載。來源過期是獨立觀察；原件可驗證且基礎完整時，仍可描述其歷史回撤，不恢復目前執行資格。

## 區段定義

- 保存 `initial_cash` 是訊號日索引 0；252 個保存淨值接在後面，總共 253 個點。
- 沒有進行中回撤時，淨值大於或等於高點就更新高點；相等平台取最後一天。
- 首次低於該高點時開始區段並固定高點。谷底只在嚴格更低時更新，相同谷底取第一次。
- 首次回到或超過固定高點時恢復。下一段使用這個恢復點或之後更新的高點。
- 已恢復完整區段長度為 `recovery_index - peak_index`；水下交易日數不包括恢復當日。另列高點至谷底、谷底至恢復間隔。
- 期末未恢復區段的恢復日期、恢復淨值、完整區段長度、已完成水下日數與谷底至恢復時間是 `null`。另保留截至期末已觀察的間隔、水下日數、谷底和深度；不推估未來。
- 所有時間是 XNYS 觀察交易日間隔，不是日曆天。區段固定按發生時間排列，不排名。
- 沒有回撤時，最大回撤與區段／水下計數是已知 `0`，區段長度是 `null`。

最大回撤是最深區段的負百分比 `(trough_nav / peak_nav - 1) * 100`。它必須與原件 `metrics.max_drawdown_pct` 相符；使用 `math.isclose`，絕對容差 `1e-9` 百分點、相對容差 `1e-10`。差額、雙方原值及容差皆保留。超過容差使整份分析不可用，不修改原件。

## 唯讀 API 與 UI

`POST /api/paper/accounts/{account_id}/workflow-path-receipts/drawdowns`

```json
{
  "receipt_id": "<64 位小寫十六進位 ID>",
  "expected_fingerprint": "<完整原回條指紋>",
  "expected_account_version": 1
}
```

使用 `@store.snapshot_read` 與 query-only SQLite 快照。嚴格帳戶範圍、指紋及當前帳戶版本核對；外帳戶回條 404，損壞／指紋或版本衝突 409，成本回條與過大匯出 422。回應以有限 canonical JSON 返回，完整包住原回條與分析，上限 3 MiB，`Cache-Control: no-store`。超限整份拒絕，不裁切。沒有第二個下載端點；UI 保存已接受的原始 response text，下載相同 bytes，不重新分析。

同帳戶版本改變或短暫核對中，所選回條草稿保留，已接受分析清除；切換帳戶清除全部。請求可取消，連點不重送，過期回應不接收。空選擇與損壞原件不可送出；未恢復狀態突出顯示，小螢幕允許表格區內水平捲動，長下載按鈕換行。
