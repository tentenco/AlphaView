# 下一輪 AlphaView Harness：工作區恢復與研究接續

這份清單供使用者決定下一輪優先順序；全部是**尚未完成的提案**，不表示已支援還原、研究階段或比較書籤。建議先交付 P1 的離線恢復工具，再選一項 P2；不要把所有項目塞進同一輪。

## 已完成的基礎與本輪不重做的功能

依目前 [README](../README.md)，已有 250／500／1,000 檔候選池、篩選與排序、瀏覽器 presets、選股與比較 CSV、研究筆記／tags、2–5 檔共同日期比較、回測、持股匯入預覽、資料品質、風險覆蓋、排程及儲存清理。備份 ZIP 已能下載；[備份預檢](backup-preflight.md) 能唯讀驗證 current 與已登錄 legacy schema，**尚不能還原**。

下一輪開始時，先以新 checkout 的 README、測試及 schema allowlist 核對狀態；本文件不取代實際相容性檢查。競品的完整功能清單也不作為必須一次實作的範圍。

## P1：可驗證、可回復的本機備份恢復

**使用者成果：**選一份 ZIP，先知道它是否可恢復、將恢復什麼、哪些內容需要遷移或重算；驗證完成後能開啟隔離的恢復工作區，原工作區保持可用。

第一版採離線 CLI／本機預覽報告，將資料恢復至**新目錄**。網頁上傳與覆蓋正在運作的資料庫不列入第一版。以下三步依序驗收，不以「預檢通過」代替恢復演練。

### P1-A：恢復計畫與版本相容性預覽

- 重用既有 ZIP 資源上限、hash、SQLite 完整性、精確 schema 辨識及設定 allowlist；不要另建較寬鬆的解壓路徑。
- 報告列出輸入備份 hash、已辨識 schema、必要遷移步驟、各類資料筆數、執行中作業與排程狀態，以及需重算的舊研究結果；預設不列私人持股值或筆記內容。
- `current` 可進入 staging；已登錄 `migration_required` 僅走明確編碼的遷移。未知 schema 停在相容性審查，不能當成已損壞，也不能自動執行其 SQL。
- 預覽綁定備份 hash、工具／遷移版本及目標路徑；輸入檔改變、目標已存在或計畫過期時，要求重新預覽，不能套用舊確認。

**驗收案例：**目前格式、已登錄早期九表、revision 前版本、缺少輸入版本的 legacy 都有隔離 fixture；未知 schema、損壞 ZIP、路徑穿越、超限、hash 不符、STOP／逾時各有明確結果。預覽前後原 ZIP 與目前工作區資料完全不變，且不連網、不啟動排程。

### P1-B：在 staging 中遷移與恢復演練

- 只在私有新目錄產生可開啟的候選資料庫；每個 legacy 路徑有確定的轉換順序及失敗清理。使用應用程式可信的 schema 建立／遷移邏輯，不採用備份中未知的可執行 schema。
- 檢查遷移後 SQLite integrity、必要欄位、revision triggers 與資料筆數；核對筆記內容、持股與價格資料的語意保留。舊快照缺少 provenance 時保持 unknown，不能補造 current token。
- 恢復後排程預設停用；保留可檢閱的原設定與歷史 attempt，不自動追補作業。備份中的 running job 轉為明確「恢復前中斷」狀態，不重新下達下載。
- 瀏覽器 presets／股票池上限另外預覽，預設保留使用者**當前瀏覽器設定**。選擇套用時再驗證既有 schema；有同名 preset 時顯示差異，由使用者選保留或另存，不能靜默覆蓋。
- 恢復工作區必須有新的識別或等價的完整快取失效機制；舊分頁不能因相同 counter 誤認為資料沒變。歷史快照 provenance 可供審查，但不得因恢復而宣稱其與新工作區當期資料一致。

**驗收案例：**空庫、含 saved notes、含 enabled schedule／running job、舊引擎回測、legacy unknown snapshot、重複 preset 名稱、失效 numeric filter、目前瀏覽器有不同 1,000 檔偏好。任何一步失敗、程序 crash、磁碟不足或 STOP，皆不能改動原工作區；可刪除 staging 後重試。不同復原步驟的再執行必須拒絕不明狀態或可安全續行，不產生重複資料。

### P1-C：開啟與回復的使用者檢查清單

- 先以獨立 port／明確工作區名稱啟動 staging，提供持股、筆記、來源覆蓋、選股／回測 stale 標示、排程停用及設定預覽的唯讀檢查步驟。
- 預設成果是可開啟的新工作區。若下一步加入正式切換，需另有「關閉服務 → 保存目前工作區的完整一致備份 → 明確確認目標 → 切換 → 健康檢查 → 失敗回復」流程；不能直接覆寫 live `.db` 或遺漏 WAL。
- 在切換前要求使用者處理未儲存筆記／表單草稿；不得用自動 reload 消除草稿。確認後如果工作區版本再變，重新預覽。切換後其他分頁顯示工作區已更換並要求重新載入，不能繼續以舊版本寫入。

**驗收案例：**恢復後能讀取 synthetic notes／持股、舊結果正確提示重算、排程不觸發、原工作區仍能重新啟動；候選啟動失敗與切換中斷均能回到先前工作區。輸出 JSON／HTML 演練證據記錄版本、筆數、檢查結果與回復路徑，不放私人資料值。

**開始前的必要條件：**確定這一版只恢復到新目錄；鎖定支援的 schema 指紋及遷移 fixture；準備足夠 staging／回復空間；測試不得使用或覆寫使用者真正的備份。正式切換另列明確交付項，不因完成 CLI 預覽就視為已授權切換。

## P2-A：候選研究階段，接續選股到筆記

**使用者成果：**將候選標記為「待研究／研究中／持續觀察／封存」，下次能回到自己的研究進度。這是整理工具，階段不代表買賣訊號。

**範圍：**獨立於 shares／cost 的本機候選記錄；從既有選股／個股頁加入並附選用的一句理由。清單提供階段與標籤篩選，連到既有筆記與個股頁。先固定四個階段，不做拖拉看板、自訂自動規則、價格通知或下單。

**驗收案例：**

- 加入候選不新增持股數量、不改成本、不觸發行情下載；重複加入顯示既有記錄。
- 標的離開目前市場池後，研究記錄仍保留；資料缺失／價格過期有明示，不能使用上一份 signal 當作目前結果。
- 階段修改採版本檢查；兩分頁更新同一筆時，409 保留本地草稿並可檢視最新值，不默默 last-write-wins。
- 切換 scope／日期、排序與重新整理不丟失尚未儲存的理由；日期快照只作來源註記，不能把歷史快照當目前資料。
- 封存可復原；首版不提供永久刪除研究筆記的連動動作。新增資料納入備份、預檢 schema 登錄與恢復 fixture。

**依賴與界線：**先決定一個 symbol 一筆工作區研究記錄，還是多筆獨立研究命題；建議首版一筆。沿用 notes tags，不重做現有筆記編輯器或篩選 presets。新候選記錄不得改變原有 RPS 股票池。

## P2-B：保存比較組合，讓研究可接續

**使用者成果：**將已提交的 2–5 檔＋60／120／252 日比較設定另存名稱，下次可重開並明確重新計算，免每次重新選取。

**範圍：**保存設定與最後一次結果的來源摘要，不把書籤當成永久有效績效。優先沿用現有 Comparison 的選擇、覆蓋與 CSV，不新增演算法或外部 benchmark。比較組合與 Screener presets 分開命名。

**驗收案例：**

- 「儲存這份比較」使用目前**已提交結果**的 symbol／window；如果畫面 draft 已改，明確讓使用者選保存 draft 設定或結果設定，不混用兩者。
- 重開書籤先顯示設定；重新 GET 為明確動作。工作區 revision／引擎改變時標示需要重算，舊結果與 CSV 維持其原始來源標記。
- 書籤成員已不在可比較股票池時保留名稱與原因，讓使用者替換；不足兩檔有效成員不偷偷用其他標的補齊。
- 刪除可取消或復原；改名／覆蓋有版本衝突處理。若採瀏覽器儲存，storage event 偵測跨分頁變更且保留 draft；若採 DB，使用 version／409，不另寫無衝突保護的儲存路徑。
- 當前未儲存比較選擇或筆記存在時，開啟另一組合須保留草稿或明確確認。匯入備份的同名組合不能覆寫目前設定。

**依賴與界線：**先決定書籤存 DB 或瀏覽器；建議 DB，以便和恢復流程一起驗收。若選瀏覽器，擴充 backup allowlist／預檢版本必須與 UI 同步。首版不做分享連結、多使用者同步或背景自動跑比較。

## 後續決策：多使用者／公開部署另開專案範圍

現況是 loopback 本機工作區。不要把加一個登入頁視為已具備可公開部署能力；本輪 P1／P2 不包含公開網站或共享使用者資料。

下一輪若要評估部署，先交付決策文件，回答：單一可信使用者遠端存取，還是多人各自工作區？誰可讀寫成本與筆記？行情授權是否允許預期的儲存／展示方式？誰負責備份、還原與排程可用性？

確定模式後才另列實作與驗收：身份與 session 管理、每個 API／job／下載的工作區授權、寫入與取消作業的權限、跨使用者快取隔離、TLS／安全設定、資源與排程限制、部署及恢復演練。驗收至少包含他人 symbol／notes／CSV／備份不可讀取、舊 session／同時編輯衝突、部署中斷與 rollback；市場資料權利的結論須以當時官方條款另行核對。

## 下一輪交辦與停止點

| 順序 | 可交辦成果 | 停止／交接條件 |
| --- | --- | --- |
| 1 | P1-A 預覽契約＋current／legacy fixture | 未知 schema 保留拒絕；列出支持與不支持範圍 |
| 2 | P1-B 隔離遷移＋恢復演練報告 | 失敗不碰原工作區；current settings／schedule 不被默默套用 |
| 3 | P1-C 新工作區啟動檢查 | 使用者可檢查並返回原工作區；正式替換另行確認範圍 |
| 4 | 擇一 P2-A 或 P2-B | 版本衝突、draft、stale 資料、備份相容性全部可驗證 |
| 5 | 部署決策文件（選用） | 沒有決策前不開 public listener，不承諾多人服務 |

每項結束應留下：更動檔案、測試案例與結果、可重現的失敗／已知限制、合成資料的本機 HTML review，以及下一個最小工作單位。Harness 到期先停止新增功能，整理實際通過與尚未驗收項；不能用規劃文件代替已完成的實作。
