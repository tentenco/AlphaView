# 保存工作流的逐標的損益歸屬

方法版本：`alphaview-workflow-path-attribution-v1`。這是既有 `alphaview-workflow-path-validation-v1` 單一路徑的帳務拆解，顯示每個保存候選的美元損益、費用及對原始模擬資金的貢獻百分點。沒有 schema 變更、帳戶寫入或原路徑方法改寫。

## 同一路徑與同一份歷史

端點在單一 `@store.snapshot_read` 唯讀快照內只呼叫原路徑 `evaluate` 一次，原始回應完整保留於 `baseline`。原路徑可用時，以相同完整歷史 universe、相同完成交易日及相同 `_load_history` 邊界重新讀取原始日線，核對其 SHA-256 與原路徑 `history_fingerprint` 完全相同。RPS 使用原 universe，不能只讀最終入選標的。

沒有重新選股、改權重、重跑單一標的路徑或最佳化。持股從原始零部位開始，依保存成交逐筆重建；買入的股數變動為正，賣出為負。所有保存候選按原順序保留，包含整段未持有、未成交的候選。

## 損益公式與必要價格

對標的 s、交易日 t，令 `q₋` 為前一收盤股數、`Δq` 為當日原始買賣股數變動、`q = q₋ + Δq` 為當日收盤股數、`C₋` 為前日未調整收盤、`C` 為當日未調整收盤、`O` 為原始開盤成交價、`F` 為該標的原始成交費用：

`net_pnl = q₋ × (C − C₋) + Δq × (C − O) − F`

實作使用代數等價式，避免要求會抵消的價格：

`net_pnl = q × C − q₋ × C₋ − Δq × O − F`

- `q₋ > 0` 才需要前日收盤；`q > 0` 才需要當日收盤；當日有成交才需要開盤價。價格必須有限且為正，不能使用舊價或調整價代替。
- 完整退出當天只需要前日收盤及當日開盤，不需要當日收盤；後續零持股、零成交的日子不需要價格。
- 原始成交開盤必須與重新讀取歷史完全相同，股數乘開盤價須與保存成交金額在數值容差內一致。
- 費用歸屬其成交標的，只扣一次。`gross_pnl` 是費用前損益；`net_pnl = gross_pnl − fees`。成交筆數以個別買／賣明細計，成交金額是買賣雙邊絕對金額合計。
- 現金利息沿用原路徑明示的零假設，`cash_interest_pnl: 0`。沒有股息、拆股權益或機會成本補估。

`contribution_pp = 100 × net_pnl / baseline.metrics.initial_cash`

分母始終是原始模擬資金，目前為 100,000 美元。單位為**百分點**，不是該標的投入金額的投資報酬率、金額加權報酬率或相對基準 alpha。標的貢獻可相加，合計須核對全路徑資產增減與原路徑報酬。

## 完整退出的浮點股數尾差

只有原始決策明確不再包含該標的、當日有原始賣出且先前有持股時，允許將 `abs(ending_shares) <= max(1e-12, 1e-12 × prior_shares)` 的浮點尾差歸零；原移除數量保留在每日與全期 `quantity_roundoff`。

仍在原始目標中的極小部位一律不歸零，仍須取得後續必要收盤。這不是重新分配權重或任意忽略小部位。無法符合原始決策的股數重建會標記不可用。

## 每日及全期對帳

每日 `reconciliation` 明列標的淨損益合計、原始 NAV 增減、重建現金、保存現金、現金加持股估值、保存 NAV，以及三種金額差額。使用：

`currency_tolerance = max(1e-8, 1e-10 × max(initial_cash, abs(previous_NAV), abs(current_NAV), Σabs(accounting_terms)))`

每日 `accounting_terms` 為各標的前日持股價值、當日持股價值、帶正負號成交金額與費用；加總絕對值。差額與容差均保留原精度，畫面用科學記號顯示細小差額，不隱藏為 0。

全期 `aggregate` 核對標的淨損益合計與 `final_value − initial_cash`、標的費用合計與原始總費用，以及貢獻百分點與原路徑百分比報酬的數值差額。全期金額容差同式，previous_NAV 採原始資金、current_NAV 採最終 NAV、accounting_terms 採各標的全期淨損益。百分點容差為 `currency_tolerance / initial_cash × 100`。這是帳務一致性條件，沒有統計通過判定、排名或推薦。

## 缺值持續傳遞

原路徑不可用時，完整保留原路徑原因與證據，所有候選 `metrics: null`、`daily: []`、`aggregate: null`，可用覆蓋為零。包含持有期間公司行動未建模等原路徑阻斷，不能由歸屬功能繞過。

任一必要價格、股數或算術缺口出現後，受影響標的當日起的每日損益／累計損益與全期指標保持 `null`，即使後來退出部位或價格恢復也不接回累計序列。組合合計與後續每日對帳同樣保持不可用。其他完整標的可保留數值，但畫面明示它們只是部分證據，不能代替組合合計。

每日帳務差異若仍為有限值，保留第一個失敗日的差額與容差供檢查，後續對帳為 `null`，不恢復合計；非有限運算則不輸出 Infinity 或 NaN。所有缺值顯示 `—`，已知零持股、零成交或零損益仍為 0。

覆蓋包含每個標的要求／可用交易日、已知未持有日與必要／可用價格數量。每日也保留價格覆蓋與實際需要的開盤／收盤值。不需要的價格為 `null`，必須搭配覆蓋與股數判讀，不能把它當成缺少必要價格。

## 邊界與 API

最多 252 個估值交易日、100 個保存候選、100 個完整歷史 universe 標的，每個歷史標的最多 3,000 根已存日線。完整 JSON 上限 16 MiB，超限回 422，不截斷候選、日期、原證據或日線支援資訊。來源非有限值回 422；來源版本、歷史指紋或已完成交易日變更回 409。

`POST /api/portfolio-agent/runs/{identifier}/path-attribution` 使用原路徑同一個嚴格輸入型別：

```json
{
  "expected_proposal_fingerprint": "64 位小寫 SHA-256",
  "expected_input_revision": "目前保存輸入版本",
  "expected_as_of": "YYYY-MM-DD"
}
```

沒有可調費率、日期、候選或最佳化參數。回應 `Cache-Control: no-store`，包含完整原路徑、原路徑指紋、兩次歷史指紋、每個標的／每日歸屬、對帳證據、覆蓋、方法、限制與完整 SHA-256。

## 介面與下載

`WorkflowPathAttribution` 接受 `run`、`enabled`、`t`。使用者按鈕才計算，連點不重複送出；計算完成後重新讀取來源，再每 30 秒及回到分頁時核對。工作流、輸入版本、日期、帳戶政策關聯或可用狀態變更，均使接受結果失效。等待替換計算及來源核對時，不能下載舊結果。

全期表保留全部候選。逐日明細使用選擇器，每次只顯示一日、最多 100 列，避免把 25,200 列同時掛入 DOM。選日期不再次呼叫 API。表格於自身容器橫向捲動，390px 版面保留閱讀路徑。

下載使用已接受回應的完整原始 JSON 文字，保留浮點字面格式、負零、指數格式、未知欄位與 null。下載前核對原文與接受物件內容及有限數值；沒有前端重算、重新序列化或額外請求，離線可依原口徑重算完整指紋。`current_at_snapshot` 只表示捕獲當時有效，不代表日後開啟仍是當期資料。

## 這不是什麼

這是同一條連續歷史模擬的帳務拆解，**不是因果 alpha、個別投資報酬、金額加權報酬、基準比較、策略有效性或樣本外證明、標的排名或交易指示**。固定候選、保存設定與目前修訂資料的事後偏差，以及原路徑成交與風控限制仍然存在。沒有建議配置、提案、收據或帳戶寫入，也不呼叫資料供應商、模型或券商。
