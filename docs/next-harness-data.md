## P0：原始／修復資料版本與公司行動 review

**問題與目前界線。** 現行資料表每檔只有一組有效日線，尚無可切換的來源版本。診斷 CLI 已能逐欄比較，但直接採用 APH repair 會大量改寫研究輸入。官方 repair 文件也說明會重建資料且可能誤判，`Repaired?` 不是全部變更的可靠清單。[yfinance Price Repair](https://ranaroussi.github.io/yfinance/advanced/price_repair.html)

**最小下一交付。** 先做唯讀「資料版本 review」：匯入既有診斷產物至獨立 staging，顯示每日期／欄位差異、缺失、價格與調整因子尺度、公司行動證據及抓取先後。建立 provider、raw／reconstructed 標記、調整方式、套件版本、抓取時間、內容雜湊及父版本。首個交付不切換現用日線；完成 review 後再拆出獨立的顯式採用工作。

**必要來源／權利／憑證。** 既有本地證據與官方公司公告即可完成唯讀版，不需要新帳號或金鑰。要判定修復正確性，還需核對交易生效日及獨立同日價格／公司行動資料；不能宣稱目前已具備。yfinance 工具授權不等於行情展示權，多人或商業部署另確認 Yahoo 適用條款。[yfinance 官方專案](https://github.com/ranaroussi/yfinance)

**驗收 fixtures。** SPY 兩格補值；APH 大範圍倍數調整；`Repaired?=false` 但調整收盤改變；既有已拆股資料避免再調整；股息與拆股不同事件；先後抓取來源自行更新；同日期重複列、缺值與非法數值。review 取消後現用 DB 與 input revision 完全不變。測試採合成資料，正式證據只作本地人工比對。

**版本與回復。** 原始版本不可變；若後續允許採用，預覽指紋需綁定當期輸入版本，提交時重新核對，整個標的／完整期間原子切換，禁止逐格悄悄拼接。保留上版並提供顯式回復；採用或回復都推進輸入版本，使掃描及回測重新計算。備份 manifest、預檢 schema allowlist 及遷移測試同步更新。

**依賴與工作量。** 唯讀 review 為中等；可採用的版本儲存與安全遷移為較大。依賴資料版本設計，之後才有可靠的來源 fallback 與 SPY 接入基礎。

## P1：有預算的重試與顯式第二來源

**問題與目前界線。** 現有使用者重試／續跑可限制標的與取消，但尚未按傳輸暫時錯誤、限流、缺日、非法價格、身份漂移安排不同恢復方式。來源錯誤不能透過無限重試消除；fallback 也不應混入原資料序列。

**最小下一交付。** 先交付同來源重試政策：對一小組明確選取的錯誤標的，顯示分類、最大嘗試次數、退避與整體截止時間；429／暫時網路錯誤才重試，確定身份／數值錯誤直接保留待查。保存每次嘗試結果，取消後不再發出新請求。第二供應者作後續獨立 adapter，先以合成回應驗收，再用少量具授權實際查詢評估，不預設自動 fallback。

**必要來源／權利／憑證。** 同來源重試沿用既有環境，沒有新付費依賴。Alpha Vantage 是一個候選對照源：adjusted daily 端點需要 API key 且文件標為 premium；compact 的 100 筆不足 MA200，需 full。此次未驗證它對 SPY／錯誤標的的真實覆蓋。方案與商業展示權須分別核准，不能將付費 key 當成再分發授權。[Daily Adjusted 文件](https://www.alphavantage.co/documentation/#dailyadj) · [方案](https://www.alphavantage.co/premium/) · [條款](https://www.alphavantage.co/terms_of_service/)

**驗收 fixtures。** 429 與 Retry-After、連線逾時、成功但缺欄、非 USD、錯身份、來源更新後恢復正常、重試期間取消、服務重啟、同時作業、預算耗盡。全部失敗不得發布部分新掃描；成功下載可保留但要按現有批次規則重算。第二來源需測調整方式不同、日期時區／提前收盤、只有 100 筆、來源期間不齊；不得把兩家單日資料拼成一條未標示曲線。

**版本與回復。** 純傳輸政策不改價格算法；新增來源須依 P0 的版本模型 staging、顯式切換、可回復。憑證只由環境或安全設定提供，不出現在記錄、備份、CSV 或 Git；測試一律假 key。回復舊來源仍保留嘗試稽核紀錄。

**依賴與工作量。** 分類退避與 mock adapter 為中等；商業來源正式接入較大，受權利與實測覆蓋限制。先完成同來源有限重試，不等待第二來源採購。

## P1：經驗證的 SPY 市場基準

**問題與目前界線。** 現有回測基準是同一股票、同起日開盤買入持有且未扣費；沒有 SPY 市場基準。候選比較也不等於回測 benchmark。SPY 最近單日曾非有限，不代表其整段歷史都不可用，但不能填補為已知價格。

**最小下一交付。** 新增可選 SPY 比較線與基準獨立狀態，保留既有同股基準。SPY 必須具 ETF 身份、USD、來源與調整方式可追溯，覆蓋回測實際起日開盤至末日收盤的全部預期交易日。以相同初始資金和明確費用假設正規化；沒有完整有效資料時僅 SPY 顯示不可用，原策略與同股基準仍可查閱。不縮短策略期間，不向前填值，也不把單一差額稱為經風險調整 alpha。

**必要來源／權利／憑證。** 若同來源重新取得完整且驗證通過的 SPY，無需新增 API 供應者；目前不保證它已恢復。若採 repair 或其他來源，先完成 P0 review／版本採用與必要授權。SPY 不是股票池內一般 equity 探索條件的替代物，需獨立 benchmark 身份與資料入口。

**驗收 fixtures。** 同日開盤／收盤定錨、跨股息或拆股、缺起日／中間日／末日、NaN／溢位、短策略期間、提前收盤、無 SPY 仍成功顯示原回測。SPY 更新但策略股未更新時，快取也必須失效；舊報告應明確保留原基準版本或標示待重算。以手算兩日價格驗證曲線與報酬，不能只檢查有畫出折線。

**版本與回復。** 回測 input fingerprint 加入 benchmark 選擇、完整基準資料雜湊、來源版本及費用定義；更改回測輸出語意時升引擎版本。舊回測保持可檢視，SPY 模組可停用回到既有同股基準，不覆寫既有結果或個人持股。

**依賴與工作量。** 已有合格 SPY 資料時為中等；資料仍不合格則先交付不可用狀態與合成驗證，不以修補數字結案。依賴明確資料版本與完整共同日期，無需先建券商下單功能。
