# Research Desk 歷史前綴完整性診斷

方法版本：`alphaview-research-integrity-v1`。入口位於 Research Desk 的單一策略診斷，下方「未來資料會改寫過去訊號嗎？」；點「比較歷史前綴」才執行，不會隨背景輪詢重跑。

這項診斷把同一份本機歷史日線切成較短的前綴，再用既有 `research_desk.Series` 與 `signals` 重新建立指標及訊號。它比較原本完整歷史與截短後重算，在相同歷史日期的進場、出場、有效性，以及該策略實際用到的指標。這能找出「加入未來日線後，已經發生的訊號改變」的具體反例。

## API 與計算範圍

`POST /api/research-desk/integrity`，body：

```json
{
  "symbol": "SYNTA",
  "config": {"strategy": "sma_cross", "params": {"fast": 5, "slow": 20}},
  "test_start": null,
  "test_end": null,
  "max_prefixes": 6
}
```

只接受一個大寫代碼與一組既有 Desk 設定；未知欄位、非有限參數、無效日期、字串或布林型切點數都會被拒絕。`max_prefixes` 為 1–6 的整數，預設 6。沒有風險、資金或成交參數，因為本功能不做回測成交模擬。

- 端點以 `@store.snapshot_read` 共用一份唯讀 SQLite 快照。回應保存 `as_of`、`input_revision`、標的、正規化設定、完整輸入、Desk 資料 `fingerprint` 與方法版本；不新增資料表、不寫入歷史紀錄、不呼叫行情供應商。
- 完整歷史的結束日不晚於 `sessions.latest_completed_session()`；可指定更早的結束日。暖機仍從本機資料起點建立，`test_start` 只限制被比較的訊號日期。
- 在建立 `Series` 前先檢查此標的本機日線總數，上限 2,000 筆。超過上限回傳 `history_limit`，不截掉較早資料、不悄悄改變暖機。即使只指定較早視窗，總讀取量限制仍適用。
- 從完整歷史第一個有效訊號日與使用者起日的較晚者開始比較。每個前綴至少比較 20 個訊號日期，並至少刪掉一筆較晚日線，因此需要至少 21 個可用日期。切點以整數等距方式確定性取樣，最多 6 個；只取一個切點時使用倒數第二筆日線。
- 最多建立 7 次 `Series`（完整歷史 1 次、前綴最多 6 次）。每次都從原始本機日線獨立計算，不把完整歷史已計算的指標切片當成重算。
- 布林訊號逐值相等比較；數值使用 `rtol=1e-10`、`atol=1e-12` 容差，避免浮點尾數差異被當成策略改寫。差異明細保留原始有限數值，不先四捨五入。

各策略比較的指標包括：均線交叉的快慢 SMA、RSI 回歸的 Wilder RSI、通道突破的前期高低點、布林策略的中軌／母體標準差／下軌，以及每日選股策略所用的均線、通道、成交量比與前收盤。所有策略另外比較調整後收盤及 `entry`／`exit`／`valid`。

## 結果與缺值

| 狀態 | 意義 |
| --- | --- |
| `no_difference_detected` | 本次所有抽樣前綴、比較日期與必要指標均可用，未檢出超過容差的差異 |
| `differences_found` | 至少找到一個具體差異；同時存在的缺值仍會列出 |
| `unavailable` | 無歷史、歷史不足、資料無效、超過計算上限，或比較期間有必要缺值／無效訊號，不能宣告一致 |

`prefixes` 列出保留至哪一天、比較起日、歷史與比較日期數、有限值比較數、差異數、缺值數及無效訊號日期數。`compared_session_pairs` 是所有切點比較日期數的加總：同一日期可能在不同切點重複出現，不能當成互相獨立的樣本數。

`differences` 每筆包含 `prefix_end`、訊號 `date`、`field`、`before`（完整歷史）及 `after`（截短後重算）。`unavailable_values` 保留缺值原因與日期；不可用數值為 `null`，畫面顯示 `—`，不以 0 代替，也不輸出 NaN／Infinity。每類明細最多 100 筆，完整計數與截斷旗標仍保留；沒有差異但存在缺值也不會得到 `no_difference_detected`。

畫面保留各切點的結果與可展開明細。連點不會重複送出；取消、切換標的／設定／日期／資料版本或離開頁面會中止接收，晚到的舊結果不會覆蓋目前畫面。回應的資料版本與指紋若不符目前診斷，需先重新執行策略診斷。取消瀏覽器請求不保證停止伺服器中已開始的同步計算，因此伺服器本身仍有獨立的成本上限。

## 這不是什麼

未檢出差異只代表**這一份本機資料、這一組設定、這些切點與日期**沒有觀察到前綴不一致。它不證明策略具有因果性、沒有任何未來資料洩漏、可以獲利或適合交易。未抽樣切點、暖機前日期、資料修訂、公司行動調整價的歷史可取得性、倖存者偏差、跨標的選樣、成交模型與參數過度擬合都不在此檢查範圍。

測試：`tests/test_research_integrity.py` 以合成日線核對所有既有 Desk 策略，並刻意注入未來收盤決定過去訊號、指標加入未來資料偏移，確認能抓到反例；另驗證缺值不通過、唯讀快照、有限 JSON 與計算上限。`web/src/ResearchDeskIntegrity.test.tsx` 驗證按需執行、明細、缺值、取消、連點與過期回應隔離。

## 離線前綴證據 JSON

完成一次前綴比較後，可按「下載目前前綴證據 JSON」保留當次完整伺服器回應。檔案包含完整請求、標的與固定設定、方法版本、交易日、input revision、歷史指紋、比較視窗與成本上限、所有切點摘要、差異與缺值明細、覆蓋計數、截斷旗標及原有警語。現行回應保留已接受的原始 JSON 文字，包含 `1.0`、`-0.0`、指數表示法、Unicode 跳脫、未知擴充欄位及原有 `evidence_fingerprint`，不重新序列化。接收與下載時核對完整解析物件與原文相符、數字皆有限；`null` 不補成零，非有限數值拒絕接收或下載，不偷偷轉成 `null`。舊回應若未包含 `request`，才補入發送時已固定的那份請求並重新序列化：這是附帶請求的舊版表示法，不是伺服器原始位元組，也不能用作原始回應指紋已驗證的證明。

下載只處理目前比較回應與必要的固定請求，不匯出整個本機狀態、診斷物件、模型文字或其他資料，也不觸發新 POST、重算或資料庫寫入。檔名的標的、日期與指紋會安全化並限長；臨時下載連結會移除，Blob URL 於下載後釋放。

比較正在執行、取消、失敗，或標的／設定／日期／來源版本／指紋／父層研究紀錄與表單身份改變時，原下載入口消失，原始文字與結果一併清除。父層忙碌期間停用；即使稍後回到舊設定或忙碌結束，舊證據也不會自動恢復，需再次按「比較歷史前綴」。研究表單修改不會把已顯示的策略診斷改算成新設定；前綴比較仍使用診斷明示的固定設定。

這是當次抽樣的離線紀錄，不是無未來資料洩漏的證明，也不保證日後來源仍相同。下載不額外查詢資料新鮮度；來源失效判斷依畫面已收到的診斷與父層身份，保存的 `as_of`／`input_revision`／`fingerprint` 只標示當次證據。重新載入頁面不會自動匯入檔案或恢復結果。
