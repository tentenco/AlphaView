# 單一股票前綴診斷收據封存

方法版本：`alphaview-research-integrity-archive-v1`；封存格式版本：`1`。

這個功能把一檔股票已保存的抽樣前綴診斷收據完整下載成 JSON，再對提供的封存檔做唯讀相容性預檢。介面必須手動按「準備完整股票封存」與「唯讀預檢封存檔」；選取本機檔案或貼上內容只改草稿。股票、研究條件或啟用狀態改變時，舊下載與預檢結果撤下，未送出的草稿保留。修改草稿、讀取其他檔案或離開原條件會取消過期請求。

## 範圍與端點

- `GET /api/research-desk/integrity-receipt-archive?symbol=SYNTA`：匯出指定股票的完整收據集合。
- `POST /api/research-desk/integrity-receipt-archive/preflight?symbol=SYNTA`：以 `Content-Type: application/json` 傳入原始封存 UTF-8 文字，回傳唯讀預檢。

`symbol` 必填，只接受一個大寫股票代碼。集合成員由資料庫內 `symbol` 的精確原始位元組決定，必須等於指定代碼的 ASCII 位元組。不做大小寫轉換、推測或重新歸類。儲存成 BLOB、但位元組正好等於代碼的列會被保留，因原始型別不是文字而不可驗證；不同位元組的列不屬於這個集合。既有歷史頁面的 20 筆分頁不限制封存內容。

兩個端點使用 `@store.snapshot_read` 的 query-only 一致快照。所有集合讀取、容量計數、輸入版本與本機重複判定都在該快照內完成；交易日於請求期間改變時回傳 409。沒有建表、寫入、刪除、歷史行情讀取或指標重算。`as_of` 取自 `sessions.latest_completed_session()`。

## 完整保留原始儲存格

封存固定保留 `id`、`symbol`、`created_at`、`engine_version`、`request_json`、`content_fingerprint`、`payload_json` 七欄。每個儲存格含 `storage_type`、`encoding`、`byte_length`、`sha256`、`content`：

| SQLite 型別 | 編碼與內容 |
| --- | --- |
| TEXT，合法 UTF-8 | `utf-8`，保留原始文字 |
| TEXT，非法 UTF-8 | `base64`，保留原位元組並保留 TEXT 型別 |
| BLOB | `base64`，保留原位元組與 BLOB 型別 |
| INTEGER | `integer-decimal`，保留有號 64 位元整數的標準十進位內容 |
| REAL | `ieee754-base64`，保留大端序 IEEE754 64 位元內容，包括負零與不可作為證據的非有限位元模式 |
| NULL | `null`，內容為 `null`、長度為 0 |

型別與內容不符合編碼契約時，預檢明確阻擋。REAL 的非有限值只作原始位元組封存，不轉成 JSON 數字或研究值。損壞 JSON、缺值、非文字型別不被補值、修復或截短。不能驗證的列仍計入原始內容完整筆數。

儲存格 SHA-256 核對原始位元組；列校驗值核對完整 typed-cell 紀錄；`set_fingerprint` 核對排序後的列校驗值多重集合，保留重複列的數量；整份 `checksum` 核對除 checksum 本身外的完整 canonical JSON。標準化規則是 Python JSON、sort_keys、UTF-8、無多餘空白、有限 JSON 數字。下載直接使用伺服器回應原文，避免瀏覽器重新序列化改變內容。

這些校驗值不是簽章、來源真實性證明或完整來源集合的外部認證。完整集合的宣告描述這次本機快照的匯出範圍；日後預檢只能核對封存內的宣告與目前本機集合差異，不能證明外部檔案未曾整批刪掉歷史。

## 預檢與狀態

預檢重新檢查嚴格 JSON（包括重複鍵、非有限數字、不合法 UTF-8 與孤立 surrogate）、版本、型別編碼、各層指紋、筆數、收據識別、保存請求、原始證據綁定與此版本理解的診斷形狀。損壞或無法驗證的內容即使和本機完全相同、或有人重新計算所有封存校驗值，仍不能成為相容證據。本機同識別但內容不同、封存內重複識別、股票不符與不支援的方法版本都會阻擋。

相容性、原始診斷結果、來源當期狀態分開呈現。合法收據可能保存 `differences_found` 或 `unavailable`，相容預檢會保留該結果，不把它改成「診斷通過」。工作區輸入版本變更只表示工作區版本不同，不宣稱這檔股票的行情已改變。來源過期仍能是合法歷史紀錄；無法核對時顯示不可用與原因。

預檢列出本機相同紀錄、缺少紀錄、識別衝突、不可驗證狀態，以及工作區用量、剩餘量、缺少識別數與預估容量。未知識別的預估總量為 `null`，介面缺值顯示 `—`。

## 逐筆紀錄檢閱

最多 500 筆回傳紀錄使用共用 `ArchivePreflightRecords` 顯示，每頁 25 筆。可選「全部／相容／不可用」，並以不分大小寫的收據 ID 子字串搜尋；搜尋是字面比對，不解析正規表示式、不改寫原識別。相容篩選只讀各列原本的 `compatible`，不以原始診斷結果或來源當前性代替它。

清單明列符合篩選／全部已回傳筆數、目前顯示範圍與頁次。原陣列順序不變，不排序或去重；相同 ID 及未知 ID 都依原始陣列位置保留為獨立列。長 ID 在收合摘要顯示前 12、後 8 字元；完整原值仍在 title 與展開內容中。未知識別明確標示「識別未知」，不推測成新 ID。每列使用原生 details／summary，可用鍵盤與滑鼠展開；390px 寬的篩選控制直向排列，完整 ID 可換行。

**篩選只改變清單呈現。** 完整相容／受阻結論、所有整份錯誤、原 coverage、來源計數及容量始終由完整報告顯示。即使選「相容」或搜尋沒有結果，整份封存受阻仍維持受阻。清單的已回傳總數不取代原 coverage 的未知宣告筆數，後者仍顯示 `—`。

改變篩選或搜尋回到第一頁；新接受的預檢報告物件重設全部清單控制。相同報告的無關重繪不清除搜尋或篩選。零結果明示無符合紀錄並停用分頁，不顯示不存在的頁面。所有操作只改前端檢閱狀態，不請求 API、不寫入 storage、不變更 hash，也不修改原回應、封存內容、檔案草稿或完整下載 bytes。

## 上限與失敗

工作區仍最多保存 500 筆前綴收據，原始收據 payload 最多 256 KiB，封存及預檢請求最多 32 MiB。工作區已有 500 筆時，不會為封存或預檢清出空間；預估加入本機缺少紀錄將超過上限時，預檢回報容量不足。既有相同紀錄不重複計入預估用量。

若完整集合超過 500 筆或完整封存超過 32 MiB，GET 拒絕整份回應，不回傳部分集合或省略儲存格。POST 逐段限制讀取位元組，超限回傳 413；媒體型別不符回傳 415；非法 JSON 或封存不相容回傳 200 的 `blocked` 報告，供介面顯示具體原因。沒有自動刪除或放寬保存上限。
