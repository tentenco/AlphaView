# 保存提案的日成交量容量研究

方法：`alphaview-execution-volume-study-v1`。這是唯讀、事後的固定股數情境，僅支援 `alphaview-paper-portfolio-v2` 保存提案。Portfolio Agent 的配置需先形成保存提案，才有可核對的股數；本功能不從工作流權重自行估算股數。

在保存提案明細按「研究保存提案容量」，先讀取來源識別，再以畫面明示的日成交量參與率計算。預設輸入顯示 1%，可改為 0–100 的有限值；伺服器沒有隱藏的參與率預設。兩次請求都不寫入資料。變更參與率、帳戶、提案、目前版本／輸入／交易日，或切離分頁後會清除舊結果；不自動重跑。

## 時序與算式

- 訊號口徑為保存提案的 `as_of` 收盤。下一個 **XNYS 交易日** 才是指定情境日；不以「下一筆有資料的日線」替代。
- 指定交易日需經 `sessions.latest_completed_session()` 確認完成（收盤後 15 分鐘）。未完成時，即使資料庫已有未來日線，也不讀取其價格與量來算情境。
- 價格是指定日的 **原始開盤價**，不是調整開盤價。保存提案的 `shares_exact`、方向與 `share_precision` 固定不變。
- 容量股數 = 指定日的全日成交量 × 使用者參與率 ÷ 100，依保存精度向下取整。情境股數 = 容量股數與保存股數的較小值。剩餘股數在指定日收盤 **僅於情境中** 到期，沒有跨日延續、重訂或轉配其他標的。
- `full`、`partial_expired`、`unfilled_expired` 分別表示情境全數、情境部分且餘量到期、情境零股且全數到期。它們不是執行層或券商委託狀態。
- 參考金額 = 情境股數 × 原始開盤價，8 位小數 half-even；沒有費用或滑價。回應同時提供股數與金額的十進位字串，保存運算精度。

**全日成交量在開盤時尚未知。** 因此將全日容量放在開盤參考價上計值，是一個明確的事後假設，不能證明開盤時可成交，也不能作為無前視的成交回放。

## 不可用與來源識別

缺少精確指定日資料、成交量負值／非有限值、開盤價無效、OHLC 品質失敗、USD 計價身分缺失、訊號原始收盤不再等於保存參考價，均保留不可用與原因；容量、情境股數、到期股數及參考金額為 `null`。不拿前一日、較晚日期或調整價填補。**明確觀察到的零量** 是有效零容量，與缺量不同。

訊號日與指定日都需有有效正數的 `adj_close/close` 基礎。相對調整因子改變超過 `1e-6`，該標的不可用；可能是拆併股、股息或資料修訂，本版不判定原因、不換算股數。指紋包含計算使用的兩日日線與資料來源身分；非法數值在可回傳證據中列 `null` 與 `invalid_fields`，不回傳 JSON NaN/Infinity。

保存提案受阻擋、未知方法、零筆保存委託會明示不可用。損壞、重複標的、股數／精度不一致的保存來源回 422，不重建成看似可用的來源。最多 100 筆委託、來源 JSON 2 MB、精度 0–6；所用正數與量最多 `1e24`，超出保持不可用。原提案因精度／最小金額略過的委託不生成新股數，列出排除筆數。

保存提案通常會在次日日線發布後變成歷史來源，仍可研究。回應分開列出保存的版本／輸入／交易日、提案指紋及目前研究快照，`source.current` 只比較這些來源身分，**不是下單許可或執行就緒性**。目前帳戶是否暫停亦不會授權研究結果送出。

## 唯讀 API

路徑基礎：`/api/paper/accounts/{account_id}/proposals/{proposal_id}/volume-study`。

- `GET .../context`：單一唯讀快照，回目前 `account_version`、`input_revision`、`as_of`、保存 `source`、指定交易日及方法。
- `POST ...`：嚴格 body `{expected_account_version, expected_input_revision, expected_as_of, expected_proposal_fingerprint, participation_pct}`。拒絕未知欄位、布林數值、無效日期及非有限值。帳戶、目前輸入／交易日或保存指紋不一致回 409。
- 路徑識別碼固定為 32 位小寫十六進位；帳戶範圍外的提案為 404。兩個端點皆 `@store.snapshot_read`，不初始化 schema、不更新 revision。
- 回應包含方法、完整請求、保存來源 metadata、每筆固定股數、兩日日線證據、日線指紋、覆蓋分母與不可用原因。沒有筆記、模型原文或金鑰。

「下載容量證據 JSON」保存已接受研究回應的原始文字，保留 `1.0`、`-0.0`、指數寫法、未知欄位、十進位字串與 `null`，不經前端重新序列化。下載前核對原文解析後與接受物件語意相同、數字皆有限；不符則拒絕。這讓依原方法驗證指紋的工具不受 JavaScript 數字格式正規化影響；研究方法 v1 與計算語意不變。

匯出不額外呼叫 API、不重新計算；原文與結果一起清除。參與率、帳戶、提案、目前版本／輸入／交易日或頁面生命週期變更，以及替換研究等待中，都不能匯出先前證據。下載仍是當次唯讀事後情境，不代表離線檢閱當下資料仍當期。

## 草稿與背景刷新

同一帳戶與同一保存提案的背景刷新會保留尚未送出的輸入文字；目前帳戶版本、輸入 revision、交易日、提案內容或暫時停用狀態變動，都不會把草稿重設為預設值。只有實際切換帳戶或提案識別時，才建立新的草稿範圍。參與率保留使用者輸入；空白或越界仍維持不可送出，不以預設值代替。

來源與草稿另外綁定研究結果。任一條件變動時，畫面立即撤下已接受結果、下載和新收據保存資格，並中止進行中的請求；不自動重跑。條件或輸入改回原值，也不能讓先前結果重新出現。較早請求的成功或失敗晚到時，不會覆蓋新狀態或解除新請求的忙碌狀態。

歷史研究回條區保持掛載，即使暫時無法執行新研究，仍可手動讀取歷史回條。只有重新接受與目前完整來源及草稿相符的原始回應，才能下載當次研究或新增保存；保留草稿不代表舊證據仍然當期。研究公式、來源檢查、API 與方法版本不變。

## 這不是什麼

本研究不是市場衝擊模型、限價觸及／先後順序模型、開盤流動性估計、券商填單、paper 帳本成交或交易建議。不推算部分成交現金如何支持下一筆買單，不驗證現金可負擔性，不計組合報酬，不重新分配權重。沒有提案／帳本／委託／政策寫入，沒有行情抓取、模型或券商呼叫。

單日開盤限價與到期情境已由 [DAY 限價研究](execution-limit-study.md) 提供，多日固定限價與指定日期到期情境見 [GTD 開盤研究](execution-gtd-study.md)。兩者都是事後研究；尚未建模的是實際盤中觸價／成交順序、部分成交後改價與券商執行結果，不能用這些研究情境推定。
