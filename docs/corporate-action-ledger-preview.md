# 公司行動帳本預覽

版本：`alphaview-corporate-action-ledger-preview-v1`。入口在 Agent 投資組合的風險控制，與公司行動來源證據並列。這是目前虛擬持倉的唯讀研究工具，只計算條件式拆併股效果；不增加 schema，不建立調整提案或入帳紀錄。

## 證據與計算資格

每次讀取以 `@store.snapshot_read` 取得同一 SQLite 唯讀快照，交易日使用 `sessions.latest_completed_session()`。只讀目前帳戶的持倉、該帳戶逐筆 `paper_ledger` 與對應的已模擬 `paper_proposals`，以及本機已保存的公司行動證據。沒有行情下載、模型、券商或其他網路呼叫。

拆併股必須同時符合：

1. 從逐筆 `simulated_fill` 重建股數與移動平均成本，與目前 `paper_holdings` 完全相符。成交提案屬於同一帳戶、狀態為 `simulated`、方法可辨識，保存委託的方向、股數與現金變化符合成交列。買入增加的成本取負現金變化；賣出移除成本依原帳本的八位小數移動平均算法核對現金變化減已實現損益。
2. 成交有效交易日可確認、均已完成且依帳本順序不倒退。收盤模擬使用保存的 `as_of`；次日開盤模擬要求 `as_of` 與 `effective_session` 一致，不用訊號日或寫入的牆鐘時間替代。進場日取最近一次由零股轉正的成交日。
3. 來源證據與目前日線指紋、資料集擷取時間對齊，沒有來源失敗，覆蓋達到此次查詢日。拆股欄存在、涵蓋進場日至查詢日，該期間沒有未知拆股儲存格，且每個預期 XNYS 交易日都有已擷取日線。股息欄缺少可以使來源整體為 `partial`；若拆股欄滿足全部條件，仍可試算拆股，股息未知狀態原樣保留。
4. 回傳拆股倍率為有限正值且不等於 1；股數倍率方向直接沿用來源 `Stock Splits`，不從收盤比率反轉推定。事件須晚於進場日，首個適用事件當日及之後不能有任何成交；同日事件與成交無法確定先後，一律不可用。

分支 `opening_mark`、缺少或跨帳戶的成交提案、未知方法、非交易日、未知時點、非有限數值與帳本差異都保留明確原因。這版採保守限制：歷史有無法驗證的列，即使之後曾平倉再進場，也不推斷其證據完整。

## 條件式算術

通過資格的事件依來源日期排序：`後股數 = 前股數 × 來源倍率`；每一步總成本不變，`後每股成本 = 總成本 ÷ 後股數`。連續拆股以之前一步的假設股數串接；反向拆股使用小於 1 的倍率。回傳數值另有十進位字串保留計算精度；這是 50 位十進位上下文的算術，不是任意精度或實際可交付的零股數量。

只要任一步產生非有限、溢位或浮點下溢結果，整條拆股鏈的效果都改為 `null`，不留下部分合計。缺值不補 0；畫面顯示 `—`。事件早於目前持倉進場日則列為 `outside_holding_period`，不把它套用到新持倉。沒有回傳適用拆股只表示保存來源沒有對應事件，不能推論沒有公司行動。

## 股息與來源限制

保留來源回傳的每股現金股息、原值、原型別和缺值原因，但 `cash_entitlement`、`record_date`、`pay_date` 一律 `null`，權利狀態為 `unknown`。來源沒有登記日、付款日、歷史權利與稅務依據；不能以現在持股乘回傳每股股息，也不能把除息日當付款日。

每檔保留完整來源摘要，包括 `source_completeness: unknown`、擷取版本、事件修訂、首次保存時間、最近擷取時間、內容指紋、擷取輸入版本、覆蓋計數、原值、比較及修訂差異。保存值與讀取時計算的 current/stale/partial 狀態分開。推算調整因子不會被提升為可用於帳本的來源事件。

來源整體完整性仍未知，所以成功試算只是「在所列回傳拆股事件及已核對本機持倉條件下」的效果。它不證明真實權利、來源的當時可得性、歷史成交價格基礎或所有公司行動都已涵蓋。

## API 與下載

`GET /api/paper/accounts/{account_id}/corporate-actions/ledger-preview` 沒有寫入 body。不存在帳戶回 404。回應包含 `engine_version`、`account_id`、`account_version`、`as_of`、`input_revision`、`read_at`、`method`、`warnings`、逐持倉 `holdings` 與總覆蓋計數。`ledger_mutated` 固定 `false`。

逐持倉包含目前帳本值 `current`、條件式最終值 `conditional_after`、每筆事件的 `before`／`after`、`ledger` 證據核對與 `source`。沒有完整資格的效果為 `null`，原因保存在 `reasons`，覆蓋分母與未知數另列。端點只看目前持有標的，不是已全部賣出的歷史權利查詢。

「下載帳本預覽 JSON」只下載前端已接受的完整 GET 回應；保留未知欄位、來源值、缺值、數值精度與讀取時狀態，不額外查詢或更新來源。帳戶、帳戶版本或方法不符時不能顯示／下載；切換帳戶、版本或重新讀取立即撤下舊結果，中止並忽略舊請求。下載時遇到非有限數值會拒絕，不暗中改為 `null`。輸出可含本機虛擬持倉等私人資料，只在使用者明示下載後寫入本機。

## 這不是什麼

- 不是帳本入帳、調整授權、股息應收或付款確認，不改變現金、股數、成本、提案、NAV、績效、就緒閘或任何執行權限。
- 不是券商核對、投資建議或操作指示。沒有外部委託與任何供應者／模型呼叫。
- 不處理拆股後再交易的成本重建、零股處分、現金補償、稅費、股息再投資、分拆或合併。
- 不是歷史價格口徑修復，也不保證公司行動資料完整或當時已知。

## 驗證

`tests/test_corporate_action_preview.py` 使用隔離的 `PANEL_DB_PATH`、合成帳戶／成交／來源擷取，檢查順向與反向拆股、成本守恆、事件後成交拒絕、進出場、帳戶隔離、次日開盤有效日、缺欄、過期、來源失敗、覆蓋缺口、非有限／下溢與一致唯讀快照；比較讀取前後所有表格及 `input_revision` 不變。

`web/src/CorporateActionLedgerPreview.test.tsx` 檢查唯讀 GET、空持倉、未知值、來源狀態、身分拒絕、連點防護、切換帳戶與版本後取消舊請求、整份 JSON 保留與非有限匯出拒絕。前端使用獨立 CSS 並沿用面板 tokens，窄螢幕不以固定寬度表格呈現事件。
