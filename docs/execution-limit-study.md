# 開盤限價與 DAY 到期研究

`alphaview-execution-limit-study-v1` 對保存的 paper-v2 提案股數做單一交易日、只檢查開盤的事後情境。在既有日成交量研究旁，可以逐筆填入選用限價，檢查原始開盤條件、日成交量代理容量、情境股數與剩餘到期股數。它不改動提案、帳本或執行層。

## 單一開盤條件

訊號日為保存提案的 `as_of`；研究日固定為下一個 XNYS 交易日，必須已完成。週末與假日由交易日曆處理，不以相隔一天代替下一交易日。只讀取這兩個確切日期的本機日線，不使用前一筆或更晚的資料補缺。

| 保存方向 | 已填限價時的條件 |
| --- | --- |
| 買入 | 研究日未調整開盤價 ≤ 限價 |
| 賣出 | 研究日未調整開盤價 ≥ 限價 |

等於限價時符合條件。留白明確表示「本情境不限制價格」，不是沿用之前的限價；價格必須是正的有限數值，上限 USD 1,000,000,000,000。每個保存標的最多一個限價，不接受新標的或多筆覆蓋。API 回傳正規化後按標的排序的限價請求與每列 `limit_supplied`、`limit_price`、`limit_price_exact`。

符合條件（或未填限價）時，沿用 `alphaview-execution-volume-study-v1` 的事後容量算法：

```text
capacity = floor_to_saved_share_precision(exact_session_volume × participation_pct / 100)
scenario_quantity = min(saved_quantity, capacity)
expired_quantity = saved_quantity - scenario_quantity
reference_notional = scenario_quantity × raw_open
```

不符合開盤條件時，**只在本情境內**將 scenario quantity 設為明確的 0、全部固定股數列為到期；已觀察到的日成交量容量仍保留。這個零來自顯式條件，不是缺值的替代品。資料不可用時，情境股數、到期股數、參考金額仍為 null，畫面顯示 `—`。

日成交量在開盤時尚未知。把整日成交量乘參與率，再以開盤價計算參考金額，是事後敏感度假設，**不能證明開盤流動性或限價能成交**。它忽略所有後續盤中機會，將情境餘量在當日收盤到期；不續單、不跨日累積、不轉移容量或重新分配權重。

## 盤中結果一律未知

每列都有 `intraday_outcome: unknown_from_daily_bars`，包括原始開盤符合限價的列。日線的高低價只能用來檢查日線資料品質，不能建立觸價順序、成交量分布、排隊順位或限價委託的成交結果。

例如開盤高於買入限價、當日最低價低於限價，本情境仍顯示「開盤不符限價；僅本情境全數到期」。這不表示真實 DAY 委託整日未成交；盤中是否、何時、成交多少仍然未知。本 DAY 頁面的情境餘量不跨日延續。

多日固定限價、餘量延續與指定日期到期情境已另有 [GTD 開盤研究](execution-gtd-study.md)，容量假設沿用 [日成交量研究](execution-volume-study.md)。這些功能都是事後研究；實際盤中觸價／成交順序、GTC 委託管理、部分成交後改價與券商執行結果仍未建模。

未計費用、滑價、價格衝擊、買賣價差、現金可負擔性與組合績效。唯一參考價是原始開盤價，沒有把不利成本加到超出限價的價格，也沒有任何成本為已測量零的主張。

## 證據與可用性

來源沿用日成交量研究的嚴格保存提案讀取：最多 100 筆固定 paper-v2 委託，精確股數字串與顯示股數一致，股數符合原提案精度，標的唯一，買賣方向及原始參考價合法。舊版、受阻擋、沒有委託或損壞提案不會產生有效情境。

必須有訊號日收盤、研究日開盤／成交量、USD 幣別身分與有效日線。訊號日未調整收盤仍須等於提案保存參考價。缺量、負量、非有限值、缺日線、研究日尚未完成、調整基礎不可用或異常日線均回明確不可用原因，不以零補值；已觀察到的成交量 0 則是有效的零容量。

兩日 `adj_close / close` 因子相對改變超過 1e-6 會使該列不可用。因子可能因拆併股或股息改變；這個檢查不猜測公司行動種類、不換算股數，也不是完整公司行動帳本驗證。

來源提案可為歷史提案，仍保留原股數；`source.current` 與 `stale_reasons` 獨立呈現它和目前帳戶／輸入／交易日的差異，不宣稱歷史提案重新取得執行資格。每次研究仍綁定使用者畫面目前的帳戶版本、input revision、最新已完成交易日與完整保存提案指紋；變動則 409。

## API 與介面

- `GET /api/paper/accounts/{account_id}/proposals/{proposal_id}/limit-study/context`：目前研究來源及單日契約。
- `POST /api/paper/accounts/{account_id}/proposals/{proposal_id}/limit-study`：唯讀計算；請求為 `expected_account_version`、`expected_input_revision`、`expected_as_of`、`expected_proposal_fingerprint`、`participation_pct`，加可選 `limits: [{symbol, limit_price}]`。

兩個端點都是 `@store.snapshot_read`，不初始化資料表、不保存結果、不變動 input revision。POST 拒絕額外欄位、重複／未知標的、非有限值、布林／字串數值與越界輸入；結果包含研究方法、容量方法、完整請求、當前及保存來源、日線指紋、逐筆日線證據、覆蓋計數與原因。

介面按需研究，無自動計算。修改限價／參與率、切換提案／帳戶／來源版本、停用或隱藏頁面會清除舊結果並中止請求。連點只會有一個研究；回應須匹配當前來源、限價假設及委託身分。409 或重算失敗不會留下看似目前有效的舊結果。

「下載限價情境證據 JSON」只下載目前接受的伺服器原文，保留原始浮點字面、null、完整來源與新增欄位；不重新計算或再發請求。非有限 JSON 不匯出，檔名會清理，Blob URL 使用後回收。它不包含模型原始文字。

## 草稿與背景刷新

同一帳戶與同一保存提案的背景刷新會保留尚未送出的輸入文字；目前帳戶版本、輸入 revision、交易日、提案內容或暫時停用狀態變動，都不會把草稿重設為預設值。只有實際切換帳戶或提案識別時，才建立新的草稿範圍。限價欄位保留使用者輸入的字面，包括尚未修正的無效內容，不會把它改成空白或先前有效值。

來源與草稿另外綁定研究結果。任一條件變動時，畫面立即撤下已接受結果、下載和新收據保存資格，並中止進行中的請求；不自動重跑。條件或輸入改回原值，也不能讓先前結果重新出現。較早請求的成功或失敗晚到時，不會覆蓋新狀態或解除新請求的忙碌狀態。

歷史研究回條區保持掛載，即使暫時無法執行新研究，仍可手動讀取歷史回條。只有重新接受與目前完整來源及草稿相符的原始回應，才能下載當次研究或新增保存；保留草稿不代表舊證據仍然當期。研究公式、來源檢查、API 與方法版本不變。

## 這不是什麼

這不是限價單的執行模型、實際部分成交、券商委託狀態、撮合回放、開盤可成交性、交易建議或授權。它不修改既有 close-fill、次日開盤佇列、預覽或券商語意，不呼叫資料供應商、模型或券商，也不建立／接受提案或發送委託。

合成測試涵蓋買入／賣出／等價邊界、日低價碰觸仍不推定成交、明確零與未知、容量向下取整、受阻擋來源、原提案股數、交易日與版本衝突、只讀快照和跨帳戶拒絕。UI 測試檢查選填空值、非法數值、來源與假設身分、連點／切換中止、失敗後清除及精確 JSON 下載。
