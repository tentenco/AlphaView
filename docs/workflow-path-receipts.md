# 工作流歷史路徑與成本情境回條

`alphaview-workflow-path-receipt-v1` 把已檢閱的保存設定路徑或成本情境，保存為不可變的本機證據。`path_validation` 和 `path_costs` 是兩種明確、互不混用的種類；原方法與資料限制照樣適用。

這不是什麼：回條不是提案閘門、可執行來源、交易授權、策略獲利或樣本外證明。保存只新增回條，不寫入工作流、模擬帳戶、持倉、帳本、提案或研究結果，也不呼叫模型、供應商或券商。原工作流未綁定帳戶時，帳戶只是歸檔關聯，不能解讀為該帳戶的歷史績效。

## 保存契約

API 基底為 `/api/paper/accounts/{account_id}/runs/{run_id}/path-receipts`。

POST 需要 `kind`、完整原始計算 `request`、`expected_account_version`、`expected_evidence_engine_version`、`expected_evidence_fingerprint`。路徑請求包含預期提案指紋、輸入版本與交易日；成本請求另外包含完整費用與滑價陣列。API 不接受客戶端績效或證據內容，未知欄位、種類混用與非有限輸入均拒絕。

第一次保存時，伺服器在一致唯讀快照內取得保存工作流及帳戶／標的政策，重算原方法，要求完整證據指紋和已檢閱結果一致。快照關閉後，進入 `BEGIN IMMEDIATE` 再核對輸入版本、完成交易日、完整工作流紀錄、帳戶版本、政策與各方法版本；中途變更就回 409，不留下半批資料。

保存的原始 canonical JSON 包含請求、完整證據、原保存工作流、帳戶／政策快照、來源與方法指紋、建立時間及 advisory-only 政策。內容以排序鍵、無額外空白、UTF-8、有限 JSON 編碼並計算 SHA-256，不丟棄精度、不截短曲線或成交明細。資料不可用時也能保存，只要來源完全綁定；原缺值及原因保留，不填補成零。

回條識別為帳戶、工作流及正規化保存請求的 SHA-256，識別不加入目前執行中的回條版本。相同請求重試先查歷史，內容有效就返回同一份 payload、建立時間及指紋；即使現在方法、帳戶或資料已變更，也不重算或改寫歷史。回應另列此次讀取的 `currentness`；歷史回條重播不代表當期資格。

## 範圍、容量與完整性

DDL 只有 `workflow_path_receipts` 與一個帳戶＋工作流＋時間索引。每筆請求最多 16 KiB、完整回條最多 2 MiB；每帳戶最多 50 筆、整個工作區最多 250 筆。超限明確拒絕，不自動刪除、截短、匯入或覆寫。

GET 清單固定以帳戶及工作流為範圍，可用 `kind` 限定種類；每頁最多 20 筆，offset 最多 250。明細及下載也必須使用相同帳戶和工作流路徑，不能以另一帳戶讀取已知的回條 ID。所有讀取使用 `@store.snapshot_read`，不執行 DDL 或重算。

每次讀取都驗證 canonical bytes、回條／內容／證據指紋、請求與種類、保存來源、帳戶／工作流綁定及時間格式。無法驗證時，`integrity.available=false`、`currentness.current=null`，歷史證據與績效留空，下載及相同請求重播均拒絕；不修補原紀錄。

有效歷史證據可以和「目前來源已變更」或「目前來源無法核對」同時存在。來源資格核對完整原工作流及帳戶政策，並比對目前輸入、完成交易日、路徑、成本、配置器、掃描、工作流及回條方法版本；工作區版本不同不等於宣稱每個標的日線必然變更。

`GET /{id}/evidence.json` 必須提供 `expected_content_fingerprint`。下載返回 SQLite 保存的完整回條原始字串及相同 ETag，不經 JavaScript 再序列化。UI 同時核對回條識別、帳戶／工作流／種類、ETag 及原始 UTF-8 bytes 的 SHA-256，再建立下載檔案。

## UI 整合

`WorkflowPathReceipts` props：`account: {id,version} | null`、`run`、`kind`、`enabled`、`t`，另可傳入已檢閱的 `evidence` 及完整 `request`。主畫面應把它放在路徑／成本元件內、顯示結果條件之外。只要選了帳戶和保存工作流，就可手動讀取歷史；只有來源已核對且請求一致的證據可保存。

元件不自動保存、載入、重算或套用設定。帳戶、工作流、證據或請求變更會取消待處理請求，晚到回應不會顯示在新範圍。歷史明細分開顯示當時證據與此次來源資格，保留基準資產路徑、績效缺值及成本情境表；完整決策、成交、原設定與政策位於下載回條。

## 驗證

`tests/test_workflow_path_receipts.py` 使用合成帳戶及行情，涵蓋兩類回條、原數值與原始 JSON、歷史重播、不可用證據、容量／大小、錯誤輸入、錯誤帳戶／工作流、快照與寫入競爭、並行重試只存一筆、保存後損壞及未知目前來源。`WorkflowPathReceipts.test.tsx` 驗證明確保存、重複點擊、歷史讀取、原資料／資格分離、空值、晚到回應、範圍錯誤，以及原始下載 bytes 與指紋。
