# 比較兩份保存工作流

方法：`alphaview-workflow-comparison-v1`。在保存的 Portfolio Agent 工作流中，從已載入的歷程選另一筆作為基準，再按「比較保存紀錄」。歷史或受阻工作流也可檢視；沒有另一份保存紀錄時不發送請求。

比較讀取兩筆保存 JSON，並列選入標的、逐標的狀態與分數、目標權重、現金、設定及來源身份。**不重新跑策略或配置器**，不使用新行情修補舊結果。設定差異與方法／來源差異分開列出；沒有紀錄的設定不退回今日預設值。

## 差值與缺口

所有差值都是「比較紀錄 − 基準紀錄」。分數只有在兩份紀錄的工作流方法版本相同且兩側都是有限數值時才計算；方法不同或缺失仍顯示原分數，差值為不可用。權重與現金差值單位為**百分點**，只是兩份可用保存配置的算術，即使配置方法不同也不代表因果。

未記錄的標的、欄位、`null`、非有限或超範圍數值保留未知，UI 顯示 `—` 與原因，不推定成零。明確保存的零可以比較。受阻或狀態不明的工作流，其目標與現金一律不可用，即使其中留有數值；候選分數仍可按原值檢視。候選清單或候選狀態不完整時，選入集合及集合差異也保持未知，不宣稱沒有選入。

畫面顯示聯集標的數及兩種差值的可用覆蓋計數。已知相同的設定不重複列出；兩侧都缺值不視為相同。

## API、版本與快照

`POST /api/portfolio-agent/compare` 是按需唯讀端點，輸入只接受：

```json
{"baseline_run_id":"saved-baseline-id","comparison_run_id":"saved-comparison-id"}
```

兩個 ID 必須不同、長度 1–100，僅英數字、底線或連字號；不接受額外欄位或型別轉換。端點使用 `@store.snapshot_read` 及 `Cache-Control: no-store`。兩筆保存值及來源當期判斷共用一致的 SQLite 讀取快照。找不到紀錄回 404；損壞、重複或超上限紀錄回 422，不截斷為部分成功。

每筆保存 JSON 上限 2,000,000 字元；每筆候選與目標標的聯集至多 100 個，兩筆比較至多 200 列。回應保留兩邊 run ID、保存提案指紋、工作流／選股／配置器方法版本、交易日、輸入版本與帳戶政策身份；回應頂層另有比較方法版本與此次讀取的交易日／輸入版本。

**保存值與當期標示的來源不同**：表格值全部來自保存 JSON；只有 `current`／`stale_reasons` 讀取目前本機版本、交易日與帳戶政策，逐筆獨立判斷。身份不完整時 `current` 為 `null`。標示只代表此次比較快照，不會自動追蹤之後的變更，也不把歷史值改算成今日數值。

切換基準、工作流或已知來源身份時，畫面清除結果並中止等待；父層以帳戶身份綁定元件。連點不重複提交，重新比較先移除舊結果，失敗不保留成功假象。收到錯誤 run ID 或提案指紋的回應不顯示為有效比較。

## 下載比較 JSON

「下載保存比較 JSON」匯出畫面目前接受的完整伺服器回應，不再呼叫 API。所有已解析的 JSON 值都保留，包括 `null`、來源身份與 `current`／`stale_reasons`、覆蓋計數、警告及前端尚未認識的巢狀欄位；不從表格重建資料，也不套用表格的數字四捨五入。檔案是該回應的 JSON 序列化，並非原 HTTP 回應的逐位元組副本。

尚無有效結果、比較等待中、切換基準／工作流／帳戶或已知來源版本後，下載停用；失敗或身份不符的回應不能取代為可下載結果。下載不重新判斷來源是否當期，檔案中的當期標示只屬於原比較快照。檔名含比較交易日與兩筆 run ID，清理特殊字元並限制長度；檔案內容中的原值不改寫。若出現非有限數值或瀏覽器拒絕下載，顯示錯誤，非有限值不會被暗中轉為 `null`。

## 這不是什麼

這不是績效比較、參數敏感度實驗、最佳化、回測或因果分析。行情、來源、方法與設定可能同時改變，分數／權重差值無法證明某一設定造成結果。功能不選擇較佳方案、不套用目標、不建立提案、不改帳戶、不送單、不新增資料表，亦不呼叫外部資料源或模型。原紙上提案的來源與版本閘門仍獨立運作。
