# 選取保存試驗的 CSCV 排名穩定性

方法版本：`alphaview-workflow-path-cscv-v1`。這是使用者明確選取 3–8 筆同帳戶已保存歷史路徑回條的排名穩定性診斷。只讀驗證原件，不重跑路徑、不重新抓價格、不新增試驗或推薦設定，沒有 schema 或帳戶寫入。

## 方法來源與本功能範圍

Bailey、Borwein、López de Prado、Zhu 的 [The Probability of Backtest Overfitting，Algorithm 2.3 與 §3.1](https://www.davidhbailey.com/dhbpapers/backtest-prob.pdf) 描述同步試驗矩陣、等長時間區塊、所有半數區塊與其補集，以及 IS 最高者的 OOS 相對名次和 logit 分布。

本功能固定 252 日、6 個區塊與 20 組切分，另明示下述同分延伸。結果**只描述選取的保存試驗**。未保存、被捨棄或未選取的探索試驗數量與結果未知，因此不能把它稱為完整策略發現搜尋的 PBO，也不能宣稱已校正所有多重試驗偏差。

IS／OOS 在此是既有回測報酬的選取子集，沒有重新訓練模型。各切分重用同一份報酬，持倉可能跨越區塊邊界，來源路徑也仍有固定候選、保存設定及修訂資料的事後偏差。

## 嚴格比較基礎

單一 `@store.snapshot_read` 內使用 `workflow_path_receipt_comparison._read` 驗證每份回條的範圍、原件內容與預期指紋，再以同一個 `_basis` 核對每份回條與第一份原件，第一份也自我核對。

所有試驗必須同為 `path_validation`，且完全符合：

- 相同保存回條、證據、路徑、工作流、掃描與配置器方法版本，以及相同路徑方法文字。
- 相同完整原始歷史指紋、相同候選與 RPS universe（包含保存順序）。
- 相同完整期間、起始訊號邊界、252 個不重複且嚴格遞增的估值日期，以及完整決策和估值涵蓋。
- 相同正值初始資金、基準費率與滑價假設，以及必要的有限原始指標。

不取日期交集、不重新對齊、不補值、不重設本金、不刪除不相符試驗。任何不相符都保留全部原件、原因及全部 20 組切分，但同步矩陣與合計不可用。不可用原路徑也不能被移除後用其餘試驗計算。

策略權重、配置限制、完整工作流設定、符號政策與保存再平衡頻率可不同，完整差異逐欄列出。來源版本的差異不自行等於不可比較：已過期但仍能驗證且比較基礎相同的歷史原件仍可用，`currentness` 是另一項當次觀察。

## 試驗識別與重複設定

請求不能重複選取相同回條 ID。完整設定定義為以下資料的 canonical finite JSON：

1. `baseline.settings`，包含 `window_sessions`、`rebalance_sessions`、初始資金、費率、滑價、完整工作流請求及綁定符號政策。
2. `saved_workflow.request` 與 `saved_workflow.workflow_kind`。
3. 保存的 `candidate_symbols` 及 `rps_universe`。

對完整定義取 SHA-256，而不把回條 ID 或工作流 ID 當作不同策略設定。相同完整定義形成明示的 `duplicate_configuration_groups`，合計不可用，原件不刪除或合併。這項檢查辨識完全相同的保存設定，不宣稱辨識所有語意等價的策略。

不同設定即使產生完全相同的報酬矩陣仍是合法試驗，依同分規則保留。不能僅因報酬相同就刪除試驗。

## 同步每日淨報酬矩陣

各試驗依原始未調整收盤 NAV 建立每日簡單報酬：

`rₜ = Vₜ / Vₜ₋₁ − 1`

第一日的 `V₀` 是該原路徑保存的初始模擬資金。其餘分母皆為上一個原始估值收盤，包含當日原始成交與費用對 NAV 的影響。使用比率，不是百分比；不使用 log return、個別標的報酬或扣除基準的報酬。沒有區塊邊界重新買入、部位歸零、再平衡或費用重算。

每一列是同一交易日，每一欄是同一份所選回條，保持使用者選取順序。任何無法有限表示的每日報酬，使完整同步矩陣不可用；不截斷極端值、不填入零，也不刪日期。

## 固定區塊與排名指標

第 1–6 區塊依序涵蓋原始矩陣的第 1–42、43–84、85–126、127–168、169–210、211–252 列。每次從六個區塊取三個作為 IS，其餘作為 OOS，全部 `choose(6,3) = 20` 組均保留。每側恰有 126 列，依原時間順序串接；每組的補集也以另一組 IS 出現。

每個試驗在每一側使用同一個固定排名指標：

`mean = Σrᵢ / 126`

`sample_sd = sqrt(Σ(rᵢ − mean)² / 125)`

`rank_metric = mean / sample_sd`

使用樣本標準差（ddof = 1）、每日無風險利率 0、不年化；數值較高者排名較高。此指標僅用於明示的切分排名，不建立策略風險品質結論。零標準差、缺值、非有限標準差或非有限算術均標記不可用；現金零報酬試驗不被指定為 0 分，而是標準差為零。

任一試驗任一側指標不可用，該切分保留所有試驗分數與原因，但沒有 IS 選取名次或比例。其他可計算切分仍保留供檢查，只有 **20/20 組全部有效**才形成合計；不對成功子集合重新分母化。

## 明示的對稱同分延伸

同分依原始有限浮點指標的**精確相等**判斷，沒有 epsilon，也不依畫面四捨五入後的文字。IS 所有並列最高者各取得該切分 `1/k` 權重，沒有依回條順序挑第一名。OOS 對全部 N 個試驗由低到高給名次 1 至 N；同分群使用平均名次。

對每個 IS 並列最高者：

`omega = OOS_average_rank / (N + 1)`

`lambda = ln(omega / (1 − omega))`

相對名次位於開區間 `(0,1)`。沒有把 lambda 裁成區間端點，也沒有依高低值建立建議配置。每筆 IS 最高者輸出回條 ID、組內權重、IS／OOS 指標、OOS 平均名次、omega 與 lambda。

每組切分彙總三個比例，整體再對 20 組各給 `1/20` 權重：

| 輸出 | 定義 | 畫面含義 |
| --- | --- | --- |
| `at_or_below_median` | 最高者權重中 lambda ≤ 0 的部分 | 低於或等於 OOS 中位數 |
| `strictly_below_median` | 最高者權重中 lambda < 0 的部分 | 嚴格低於中位數 |
| `exactly_at_median` | 最高者權重中 lambda = 0 的部分 | 恰等於中位數 |

三個比例同等呈現，不能單看包含中位數的第一項宣稱過度擬合。例如全部試驗全體同分時，三項依序為 **100%、0%、100%**；其含義是無法區分的中位數質量。沒有統計通過門檻、P 值、信賴區間或完整搜尋的機率宣稱。

## API、完整證據與界限

`POST /api/paper/accounts/{account_id}/workflow-path-receipts/cscv`，嚴格輸入：

```json
{
  "expected_account_version": 1,
  "trials": [
    {"receipt_id": "64 位小寫 SHA-256", "expected_fingerprint": "64 位小寫 SHA-256"},
    {"receipt_id": "另一份回條的 SHA-256", "expected_fingerprint": "該份回條內容 SHA-256"},
    {"receipt_id": "第三份回條的 SHA-256", "expected_fingerprint": "該份回條內容 SHA-256"}
  ]
}
```

固定 3–8 筆、252 日、6×42 日、20 組切分，沒有任意區塊、排名指標或費率參數。帳戶預期版本、回條內容指紋或核對期間的已完成交易日變更回 409；範圍不存在回 404；不符種類、嚴格 body 或完整證據超過 16 MiB 回 422，拒絕而非截斷。

回應保留完整原件與保存摘要、比較基礎檢查、設定差異與重複群、完整同步矩陣、區塊日期、全部切分的原始列索引、所有分數和同分權重、三項合計、涵蓋與原因、明示方法與限制、來源論文及完整證據 SHA-256。使用 canonical finite JSON 回應，`Cache-Control: no-store`。沒有回條、帳戶、提案、帳本或執行寫入。

## 介面生命週期

`WorkflowPathCSCV` 接受 `accountId`、`accountVersion`、`t`。使用者手動載入既有帳戶路徑回條索引，最多 50 筆；不能把尚未載入的部分當成完整索引。不可驗證原件保留在選單但禁止選取。勾選 3–8 筆後才執行一次診斷，連點不重複發送。

診斷完成後重新驗證帳戶版本與選取原件的指紋，再每 30 秒及回到分頁時核對。背景核對失敗只使結果／下載失效，保留使用者勾選草稿；使用者主動重新載入才重設選取。帳戶或版本切換會中止舊請求，忽略遲到結果。替換計算或來源核對期間，舊下載不能觸發。

介面以六個區塊卡、全部 20 切分表與可選的單切分分數／名次明細呈現。三項比例顯示同等資訊權重；缺值為 `—`，已知零仍為 0。390px 使用單欄區塊、可換行的按鈕與表格內橫向捲動。

下載直接保存已接受回應的原始 JSON 文字，保留 `1.0`、`-0.0`、指數寫法、未知欄位、null 及全部原件；不重新序列化而破壞指紋口徑。下載核對原文與接受物件內容及有限數值，不另外呼叫 API。

## 這不是什麼

這不是完整搜尋的 PBO、獨立 fold、CPCV、purging／embargo、模型重新訓練、樣本外證明、策略有效性結論、最佳配置推薦、統計 pass/fail 或執行閘門。它不修補原始回測的事後偏差與成交假設，不把歷史原件改標為當期，也不對外呼叫模型、資料供應商或券商。

## 驗證

後端測試使用獨立手算的穩定名次、兩段反轉、中位數邊界、精確同分、3／4／8 試驗平均名次、欄位置換、零變異與缺值案例；API 使用隔離資料庫中的合成原件，核對原件不變、同一唯讀快照、歷史比較基礎、重複設定、不同設定相同報酬、來源過期、範圍／版本／指紋衝突、容量與交易日變更。

前端檢查手動載入、3–8 選取、快速連點、三比例、中位數情境、不可用切分、帳戶／版本切換、背景指紋變更、勾選草稿保留、完整原始 JSON 下載及替換期間下載阻斷。主代理負責接線、真實 390px 瀏覽器及全專案五道關卡。

## 必要保存設定缺少時

若原件已通過收據完整性核對，但無法讀取完整設定定義（例如 `saved_workflow.workflow_kind` 缺少），端點拒絕整份所選試驗並回傳 409，`detail.code` 為 `cscv_trial_configuration_unavailable`。`detail.receipt_ids` 列出無法讀取設定的原始收據 ID，維持所選順序；`detail.coverage` 包含 `required_trials`、`verified_trials`、`available_configurations`、`unavailable_configurations`。

這條路徑不省略有缺口的試驗、不計算部分報酬矩陣或合計，也不重跑路徑或寫入資料。完整設定定義、指紋、方法版本與有效結果的數值／原始回應保持原樣。

介面辨識此精確錯誤碼並說明必要設定缺少、整份選取已拒絕；只有涵蓋計數和相關 ID 都與目前草稿一致時，才顯示可用／不可用設定數。勾選草稿保留，舊結果與下載撤下；其他 409 仍使用原有的來源變更提示。
