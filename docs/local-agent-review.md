# 本機模型分析的獨立人工檢閱

`alphaview-local-agent-review-v1` 為選定的紙上帳戶與保存的本機模型分析附加人工研究註記。它分開呈現人工狀態、既有保存證據驗證，以及來源目前是否有效。檢閱者不會因為按下「已檢閱」而取得新的程式或交易權限。

## 使用與意義

在組合頁的本機模型分析下，按「載入檢閱狀態」，檢查獨立程式證據與目前人工狀態，再保存固定理由的註記。沒有自動讀取或模型推論；切換帳戶、分析、來源身分或操作生命週期時會中止請求並清除舊畫面，須重新載入。409 衝突會清除可操作的舊脈絡並明確顯示尚未確認成功。人工草稿不會被手動狀態更新無聲清除。

| 狀態 | 意義 |
| --- | --- |
| `review_required` 待檢閱 | 尚未有這個脈絡的註記，或檢閱者明確重新標記為待檢閱。 |
| `reviewed` 已檢閱 | 檢閱者已看過此保存內容；不代表已驗證、已批准或安全。 |
| `rejected` 人工不採納 | 保存人工研究判斷，至少附一項固定疑慮；這不是執行控制。 |

固定疑慮為 `evidence_uncertain`、`source_stale`、`model_limitations`、`allocation_concern`、`insufficient_information`，最多五項且不可重複。沒有自由文字、私人筆記、審核者身分認證或原始模型文字欄位。

失敗或不可用的分析也可以標示「已檢閱」，但程式證據仍顯示原來的 `failed`／`unavailable`，提案資格仍為 false。相反地，人工不採納不會改寫原有 `validate_source` 或歷史授權的結果。程式提案資格只表示既有保存證據與來源條件；帳戶風險、版本、政策、暫停開關等仍須由既有紙上預覽獨立檢查。進行中的 queued／running 分析不可新增註記。

## 保存依據與失效

伺服器從本機 SQLite 重建完整分析資料列與規則工作流程資料列的指紋，並綁定：

- 帳戶 ID、版本及標的政策指紋。
- 分析／規則 ID、方法、完整內容指紋，以及既有歷史授權指紋（證據不足時為 null）。
- 保存時與目前的完成交易日、input revision；目前交易日使用 `sessions.latest_completed_session()`。
- 既有 verifier 的方法、狀態、有限的理由代碼與來源有效性。

明確綁定帳戶的來源不能在另一帳戶下註記。沒有帳戶綁定的既有歷史分析，可在不同選定帳戶下擁有互相獨立的人工歷史。

任一綁定內容改變，之前的「已檢閱／不採納」保留為歷史，但目前狀態回到待檢閱；不自動沿用。保存只在 `BEGIN IMMEDIATE` 內重新建構並核對預期版本、完成交易日、input revision 與完整綁定指紋後追加事件。交易中失敗全部回滾。事件不改帳戶版本、來源資料、input revision、目標權重、提案或訂單。

相同 idempotency key 與完全相同的正規化請求，只能在綁定內容仍相同、該事件仍為最新時原樣重播。不同請求、已被新註記取代或脈絡已改變均回 409。每次成功的新註記遞增版本；重新待檢閱也是新事件，不刪除舊記錄。

## 不可變更的歷史

「載入檢閱歷史」只讀取已保存的事件，每頁 20 筆；展開可查看當時的固定理由、獨立程式狀態、來源 ID、交易日、revision 與指紋。歷史狀態不宣稱仍符合當期資格。API 上限每頁 50 筆、offset 5000；UI 到達上限會說明更早的歷史未列出。

每次讀取都核對方法、完整內容指紋、欄位身分、版本、請求與綁定指紋，以及嚴格的保存格式。損壞事件只回傳最小 metadata、`integrity.available: false` 與原因，`receipt` 為 null；不顯示有效狀態。最新事件損壞時，不會退回更早的「已檢閱」，也不能另存一筆遮蓋問題。沒有歷史回填、刪除或保留期限機制。

本機指紋不是數位簽章。若有人可一致地重寫整套資料及指紋，本功能不能證明原始真實性；它仍拒絕超出固定格式的額外內容。

## API 與資料表

基底：`/api/paper/accounts/{account_id}/local-agent/{analysis_id}`。

- `GET /review`：目前脈絡、綁定指紋、程式證據、最新事件、有效人工狀態與版本；沒有事件時版本為 0。
- `POST /review`：只保存人工註記。
- `GET /reviews?limit=20&offset=0`：帳戶與分析範圍內的歷史及分頁資訊。
- `GET /reviews/{review_id}`：同一範圍的單筆歷史；跨帳戶或不存在為 404。

POST 必填 `expected_version`、`expected_account_version`、`expected_input_revision`、`expected_as_of`、`expected_binding_fingerprint`、`state`、`idempotency_key`；`reason_codes` 預設空陣列。版本拒絕布林、字串、負數與溢位，拒絕非有限 JSON、額外欄位、無效日期及未知理由。回應帶完整版本與綁定 provenance，`changed` 區分新事件與原樣重播。

唯一新表 `local_agent_review_events` 以事件 ID 為主鍵，並對 `(account_id, analysis_id, version)`、`(account_id, analysis_id, idempotency_key)` 設唯一約束。只在既有啟動 schema hook 初始化；所有 GET 使用一致快照且不初始化或寫表。事件沒有 cascade 刪除，原始分析之後不可用時仍可讀取已保存的歷史。

## 這不是什麼

這不是模型驗證、審批系統、執行許可、風險解除、多人簽核或績效結論。它不呼叫 Ollama、付費模型、資料供應商或券商，不更改原有預覽、次日開盤佇列、歷史授權、提案建立與交易語意。人工檢閱不能把不可用證據補成有效數字或覆寫程式失敗。

合成測試覆蓋保存與重播、競爭版本、來源／帳戶／交易日變更、失敗與缺失證據、帳戶隔離、損壞內容、只讀 GET、原有授權 byte-identical 與交易回滾。介面測試覆蓋按需載入、固定疑慮、人工與程式狀態分離、連點保護、模糊網路結果的同 key 重試、409、切換中止、歷史分頁及回應身分檢查。
