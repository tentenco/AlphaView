# 保存路徑的固定期間滾動視窗

方法：`alphaview-workflow-path-rolling-v1`。本功能只讀取一筆可驗證的 `path_validation` 原回條，以其保存淨值列出固定 21、63、126 個 XNYS 交易日的所有滾動總報酬。它不重新建立路徑、不讀取目前行情重新估值，也不更動原回條的成本假設。

## 分母與期間

原回條必須完整保存 252 個估值交易日。訊號日的期初現金是索引 0，後續 252 筆保存淨值依時間為索引 1–252。對長度 `h`、首個估值索引 `s`：

```text
boundary_index = s - 1
end_index = s + h - 1
total_return_pct = (NAV[end_index] / NAV[boundary_index] - 1) × 100
nav_change = NAV[end_index] - NAV[boundary_index]
```

第一個視窗從原期初現金接續；第二個視窗從第 1 筆保存淨值接續，以此類推。不能把視窗首個估值日的淨值當分母，否則會少算一個交易日的報酬。每筆視窗都有邊界、起點、終點的日期與索引，以及邊界／起點／期末淨值、總報酬、gross return 與淨值變動。

| 固定期間 | 起始索引 | 完整視窗數 |
| --- | --- | --- |
| 21 個交易日 | 1–232 | 232 |
| 63 個交易日 | 1–190 | 190 |
| 126 個交易日 | 1–127 | 127 |

這些是固定交易日數，不是曆月、季或半年。三種期間共 549 筆視窗，每次起點前進一個交易日，彼此重疊。

## 完整原值與不可用

沿用保存路徑比較的嚴格 self-basis：方法與估值口徑、原始資料指紋、候選／RPS 股票池、日期與期間、完整決策涵蓋、期初現金與原基準成本、必要指標都必須能核對。再要求 252 筆有限正值淨值及期初現金，日期連同前一期訊號邊界必須完整等於歷史 XNYS 交易日曆，且不能超過檢視當下 `sessions.latest_completed_session()`。

期末保存淨值與整段直接報酬會核對原回條指標；淨值絕對容差為 `1e-6`、報酬絕對容差為 `1e-9` 百分點、相對容差為 `1e-10`。原期末淨值仍須大於零，不能利用絕對容差把零或負值視為有效。回應保留計算值、原值、差額與核對結果，不覆寫原指標。

任何缺值、非有限值、非正值淨值、缺少或重複交易日、未完成交易日、運算溢位／比率下溢、涵蓋不足或核對失敗，都讓整份分析成為 `unavailable`，`horizons` 與 `summary` 為 `null`。不略過問題視窗、不對齊子集合、不排序修復、不補零或補價。原回條仍完整保留；前端衍生缺值顯示 `—`。

## 最低、最高與全部並列

每種期間機械式找出最低與最高的計算總報酬，並保留所有完全相等的 `window_numbers`，依起始時間排序。使用未經顯示四捨五入的計算數值做完全相等比較，不用顯示精度或近似容差合併並列。平坦路徑的所有視窗同時並列最低與最高；不從並列中挑一筆代表或勝者。

畫面先顯示各期間涵蓋數、第一個現金邊界、最低／最高報酬與並列筆數。明細需明確展開才呈現，每個期間每頁最多 25 筆；可選全部視窗、全部最低並列、全部最高並列，均能翻頁查看完整集合。改變明細範圍回到第一頁，不發出新的研究請求。

## 唯讀 API 與下載

`POST /api/paper/accounts/{account_id}/workflow-path-receipts/rolling`，body 嚴格限定：

```json
{
  "receipt_id": "64 位小寫十六進位回條識別",
  "expected_fingerprint": "64 位小寫十六進位完整內容指紋",
  "expected_account_version": 1
}
```

端點使用 `@store.snapshot_read`；既有回條解碼器核對原 JSON、來源識別、內容與請求指紋。帳戶版本／指紋變動或不可驗證原件回 409，跨帳戶來源回 404，非路徑回條或無效請求回 422。完成交易日在檢視期間變動亦回 409。沒有 schema、帳戶、帳本、回條或 input revision 寫入。

回應包含完整 `original_receipt`、`receipt_summary`、明示 request、方法、觀察交易日與 input revision、容差、基礎／指標核對、全部視窗與全部並列識別。原 canonical 回條 JSON 完整嵌入回應；前端下載接受時的原始回應文字，保留原件、未來欄位、數值文字與所有 549 筆明細，不從頁面上的 25 列重新組裝。完整 UTF-8 回應上限 3 MiB；超限整份拒絕，不截短。

只有使用者按鈕會載入回條清單或執行檢視。空選擇、不可驗證回條或尚未取得有效帳戶版本時不可檢視。來源版本改變會中止舊請求並清除舊結果，同一帳戶保留所選回條；切換帳戶清除選擇。晚回應、重複提交、錯誤來源、缺少視窗／並列、非有限回應及超限回應不能恢復下載。

## 全部視窗 CSV

「下載全部期間與視窗 CSV」從已接受且完整可用的分析匯出三種固定期間全部 549 筆視窗，依 21／63／126 日及原始視窗順序排列。明細的最低／最高篩選、展開狀態與分頁不影響匯出範圍。每筆保留期間、視窗編號、邊界／起始／終點索引、實際起訖日期、現金或前一期保存淨值邊界的種類／日期／淨值、首日與期末淨值、gross return、總報酬百分點數值及淨值變動。`total_return_pct` 的 `10` 表示 10%；沒有年化或顯示四捨五入。

每列均附原回條 ID、完整指紋、run ID、分析方法、`checked_as_of`、input revision、檢視時來源 currentness 與「同一路徑、重疊且非獨立樣本」標記。來源過期不會改寫歷史結果；明確未知的 currentness 為空白，真正的零報酬仍為 `0`。必要 metadata、期間、視窗、索引或數值缺漏／非有限時整份 CSV 不提供，顯示原因，不裁切、補零或忽略問題視窗。

檔案使用 UTF-8 BOM、CRLF 與 RFC 4180 引號轉義；所有文字欄位含 metadata 均加試算表公式防護，有限數值保留原精度與符號。CSV 只是閱讀便利副本，不是簽章或 canonical 證據。完整原始 JSON 按鈕仍下載逐字相同的已接受回應，保留原件、所有視窗及未來欄位。CSV 只在明確點擊時本機下載，無新請求、計算、持久化或執行權限；帳戶／版本／選擇改變及衝突沿用既有失效規則。

## 這不是什麼

549 個重疊視窗不是 549 個獨立樣本，只有一條歷史路徑。最低／最高結果不是配置建議、預測、統計信心、顯著性、通過判定、基準比較、年化報酬或交易指示。本功能不另加成本、不調整權重、不重建路徑、不呼叫行情供應商、模型或券商。

來源 currentness 只記錄檢視當下是否仍相符，與歷史分析可用性分開。過期但完整可驗證的原件仍能檢視；這不更新其市場資料或賦予目前執行資格。`execution_authority` 固定為 `false`。
