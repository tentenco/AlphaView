# 多日 GTD 開盤情境研究

`alphaview-execution-gtd-study-v1` 使用保存的 paper-v2 提案固定股數，從訊號日收盤後的下一個 XNYS 交易日開始，最多延續五個交易日。它是本機唯讀研究，不更改既有 DAY 成交量／限價研究、執行層或券商行為。

## 明確日期與來源

`GET /api/paper/accounts/{account_id}/proposals/{proposal_id}/gtd-study/context` 回傳來源與訊號日後的**確切五個交易日**，各自標示是否已完成。使用者從中選 `gtd_date`；不是「五個日曆日」，不能填週末、假日、訊號日或第六個交易日。前收盤訊號對應第一個情境交易日的原始開盤價。

`POST /api/paper/accounts/{account_id}/proposals/{proposal_id}/gtd-study` 接受：

```json
{
  "expected_account_version": 1,
  "expected_input_revision": "synthetic:2",
  "expected_as_of": "2024-01-12",
  "expected_proposal_fingerprint": "cccccccccccccccccccccccccccccccccccccccccccccccccccccccccccccccc",
  "participation_pct": 1,
  "limits": [{"symbol": "SYNTA", "limit_price": 100}],
  "gtd_date": "2024-01-12"
}
```

兩個端點皆為 `@store.snapshot_read`、`Cache-Control: no-store`，不寫資料庫。沿用既有成交量研究的保存提案驗證、帳戶範圍與內容指紋：只接受可識別的 paper-v2 保存股數及精度，至多 100 個不同標的，每標的只能有一張保存委託；重複標的來源拒絕，不會重複使用同日容量。未知限價標的、重複限價、額外欄位、布林數字或非有限數值拒絕。參與率為 0–100%，限價大於零且不超過 `1e12`。

POST 在一致快照中核對帳戶版本、input revision、目前完成交易日及保存提案指紋，不符回 409。計算結束再核對 `sessions.latest_completed_session()`，期間若跨過完成交易日邊界，也回 409。沒有發布或交易寫入。保存提案可為歷史來源，`source.current`、`stale_reasons` 與目前快照身份分開顯示；可研究歷史，不表示目前可執行。

## 每個標的逐日計算

起始剩餘股數等於保存的 `shares_exact`，限價在整個研究區間固定。每個仍有餘量且已完成的交易日，使用該標的**精確當日**原始日線：

1. 訊號日原始收盤仍須符合保存參考價；訊號與情境日日線、USD 身份及調整基礎必須可用。當日 `adj_close / close` 相對訊號日變化超過既有 `1e-6` 容差，就停止該標的。因子變化可能來自拆併股或股息；此研究不推斷原因、不換算股數。
2. 每日容量代理 = 當日完整成交量 × 參與率 ÷ 100，依保存股數精度用 Decimal 向下截位。
3. 買入只在原始開盤價 ≤ 限價時符合條件；賣出則 ≥，相等亦符合。未填限價表示本情境不限制價格。符合時，當日情境股數取已知餘量與容量代理較小者；不符合時是明確的情境零股數。
4. 已知餘量扣除當日情境股數，才延續到下一個交易日。參考金額沿用既有方法的逐日 8 位 Decimal 結果；不計費用、滑價、現金、價格衝擊或投組績效，也不把剩餘容量轉給其他標的。

即使開盤不符合限價，也不略過必要日線品質／成交量檢查來製造零結果。實際為零的成交量或使用者填零參與率，才是有資料支持的零容量。

**全日成交量在開盤時未知，只是事後容量代理，不代表開盤流動性或實際可成交。** 日線高低價只參與資料品質檢查，不推斷盤中觸價、排隊、成交先後或真實委託路徑。所有列的實際盤中結果均為 `unknown_from_daily_bars`。

## 缺口、已觀察前綴與到期

第一個缺少／無效的必要日線、調整基礎改變或尚未完成交易日，會停止該標的的後續股數推算。後面的日線即使存在且成交量很大，也不拿來補算。第一個缺口保存原因；後續列標 `blocked_by_unknown`，情境股數、後續餘量皆為 `null`。不讀尚未完成交易日的執行日線，不用較早／較晚價格或零替代。

已經完成的連續前綴會另列 `observed_prefix_end`、`observed_prefix_scenario_shares`、`last_known_remaining_shares` 及前綴參考金額。它們只是最後已知狀態，**不是未知後續日期的最終結果**。若連第一個交易日都無法評估，前綴總數保持 `null`，不捏造為零；保存起始股數仍可顯示。任何未知進程使整體 `status=unavailable`，而且沒有把可用標的加總來掩蓋未知標的。

| 狀態 | 最終股數 | 到期股數與主張 |
| --- | --- | --- |
| `scenario_full` | 已在情境中用完固定股數 | 後面日期 `not_required_scenario_full`，不再讀取無關日線；即使 GTD 尚未到也能成立。到期股數 `null`、`expiry_verified=false`，不宣稱到期已驗證 |
| `partial_expired` | 每個所需交易日都已完成且有必要證據，累積股數大於零 | 正餘量在選定 GTD 收盤於情境中到期，`expiry_verified=true` |
| `unfilled_expired` | 每個所需交易日都有必要證據，情境股數明確為零 | 全數在選定 GTD 收盤於情境中到期 |
| `unavailable` | `null` | 到期股數 `null`、不宣稱到期；只保留明示的已觀察前綴 |

回應保留每一天的完成狀態、起始餘量、原始開盤、當日量、容量、開盤條件、當日情境股數、結束餘量、來源日線、不可用原因與精確十進位字串；另含完整固定請求、方法版本、提案／日線／整份證據指紋。歷史資料可被後續修訂，這是當次快照的研究證據，不是永久的新鮮度保證。

## 畫面與離線檔案

`ExecutionGTDStudy` 使用與 DAY 研究相同的 props：`accountId/proposal/currentAccountVersion/currentInputRevision/currentAsOf/enabled?/t`。先明確讀取日期與來源，再選到期日並按研究，沒有掛載即發請求。連點受保護，取消、離頁、帳戶或來源變更中止接收，晚到結果不會覆蓋目前畫面。

同一帳戶＋保存提案內，來源 revision、完成交易日或暫時 `enabled` 改變會清除證據與已讀來源，保留尚未提交的參與率、固定限價及日期草稿。需重新讀取來源才可研究。只有切換帳戶或提案才重新建立草稿；父層不應以暫時忙碌或 refresh 值作 remount key。輸入修改再回復不會恢復舊下載。

下載保留已接受伺服器回應的完整原始 JSON 文字，包括整數型浮點、負零、指數表示法、Unicode、未知擴充欄位與 `null`。完整解析物件須吻合原文，非有限數值拒絕；下載不重新查詢或執行計算。檔名安全化且限長，臨時連結與 Blob URL 會清除。
