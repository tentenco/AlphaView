# Portfolio validation v2：方法契約草案

**狀態：UNIMPLEMENTED／待下一輪 Harness 審閱，2026-10-05。** 本文只提出方法、資料與驗收契約；沒有新增產品能力、方法引擎、端點、schema、統計通過門檻或提案資格。檔名中的 v2 是未來設計範圍，不是已發布的 `ENGINE_VERSION`。CPCV 與完整搜尋 PBO 仍未交付。

建議下一輪先完成「事前固定的候選集合＋可追溯的樣本時間＋合成切分驗收」，再決定是否實作 train/test 選擇與組合狀態重建。現有日線、保存工作流與回條不足以自行補出歷史當時可知的股票池、事件標籤或未登錄的試驗。

## 2. 先分開三種研究問題

**固定策略描述**問的是同一份規則與資料下，歷史路徑在哪些期間表現不同。**候選選擇診斷**問的是在宣告集合內，IS 選中的候選於 OOS 的相對排名。**訓練／選擇程序驗證**則要執行每個 split 的訓練程序或訓練內設定選擇，再產生該 split 的測試輸出。三者需要不同輸入，不能用相同的「驗證」標籤取代方法契約。

PBO 原論文 §2.1–2.2 特別區分「用 IS 選候選」與「估計候選內部模型」；CSCV 使用同步候選績效矩陣，並不要求所有策略都是可訓練模型。其選擇問題關心 IS 最佳候選在 OOS 相對排名落到中位數以下的事件，不是該策略未來虧錢的機率。故本專案不能把「沒有 ML fit」當成拒絕任何選擇診斷的理由；真正缺口是選擇程序、候選範圍與資料來源是否已定義。[Bailey 等人，原作者公開論文](https://www.davidhbailey.com/dhbpapers/backtest-prob.pdf#page=9)。

López de Prado 將 CPCV 描述為組合 train/test 切分與 PnL 情境的生成方法，並清除含測試資訊的訓練觀察；purging／embargo 對應標籤重疊與時間依賴。[作者方法說明](https://www.quantresearch.org/Innovations.htm)。**本草案的設計判斷**：即使未來只測 deterministic rules，也必須明定訓練側究竟選擇什麼；若完全沒有 fitting 或 train-only selection，就維持固定規則的情境分析名稱，不藉 CPCV 名稱暗示已驗證某個未定義的學習程序。

CPCV 的部分 split 可以用較晚區間訓練、較早區間測試。**由其切分結構推得的限制**：即使排除資訊重疊，也不是按當時資訊部署的單向 walk-forward 歷史。若研究目的要求「每次訓練都早於預測」，須另選時間向前的契約，不能將兩種輸出混稱為同一種樣本外證據。

## 3. 與 prospective trial registry 共用的身分與分母

本節與 [`trial-registry-contract-draft.md`](trial-registry-contract-draft.md) 協調，兩份均未實作。統計分析只能引用已封存的宣告，不自行從保存回條推回研究者做過哪些事。

| 身分／數量 | 擬定口徑 |
| --- | --- |
| `batch_id + declaration_fingerprint` | 開始前固定的研究範圍、候選 slots、方法、資料與停止條件；不能看過結果後原地改寫。 |
| `candidate_id` | batch 內固定 ordinal 對應的 slot；不以 receipt ID、績效或設定去重生成。 |
| `configuration_fingerprint` | 沿用 `workflow_path_cscv._configuration` 五欄：完整 settings、workflow request、workflow kind、candidate symbols、RPS universe；另外綁定 definition version。新增未來模型／標籤／split 設定時，需新增定義版本，不冒用原指紋。 |
| `D_declared` | 宣告 slots 數，含未嘗試、失敗、不可用、取消與捨棄者。重試不新增 slot；distinct configuration count、attempt count、receipt count 另列。 |
| `analysis_attempt` | 首版提案採第一個由伺服器提交開始紀錄的受控 attempt；source preflight 拒絕不算。開始提交後、真正呼叫計算前若中斷，仍保留 unknown，不能改成未嘗試。相同 key 的 transport retry 只是重播；不能在看過結果後取最好或最後成功的額外 attempt。 |
| `K_declared_splits` | 開始前固定的全部切分數；它是切分事件比例的分母，與候選數 `D_declared` 不同。可計算切分數另列。 |
| `historical_unrecorded_trials` | 登錄前與受控入口之外的探索仍是 `null`／unknown。最多能主張本 batch 的宣告範圍完整，不能宣稱研究者終生搜尋已完整。 |

**首版建議採保守的不完整處理**：任一宣告候選的必要績效欄缺值、指定 attempt 未成功，或任一必要 split 不完整，整體排名比例保持不可用並列覆蓋；不得把 `D_declared` 或 `K_declared_splits` 改成成功子集。這是本專案擬定政策，不是宣稱論文強制所有軟體採取同一種失敗處理。

重複設定 slots 與所有 attempts 都保留。首版統計層建議沿用現有 CSCV 的精確重複設定阻擋，不默默合併、刪除或當成獨立策略。不同設定產生相同報酬仍可形成同分。若要研究隨機 seed 重複實驗，必須先決定 seed 是候選參數還是同候選的重複測量，另訂群組權重；不能事後依結果改變定義。

既有 `workflow_path_receipts.save_receipt` 會優先重播規範化請求相同的舊回條，因此「宣告後按過保存」不等於宣告後真的執行新 attempt。未來結果關聯必須另綁 `batch_id + declaration_fingerprint + candidate_id + attempt_id + server_started_event_sequence`；舊回條保持原件，只能列 prior evidence，不能以舊內容或 `created_at` 倒填成事前登錄證據。這是 registry 與 evaluator 的共同缺口，本文沒有新增保存流程。

## 4. 每一筆樣本與資訊邊界必須可追溯

下列為**擬定的必要 manifest**，目前既有 NAV 回條不能直接提供全部欄位。資料不足時回報缺少什麼，不用固定 21 日再平衡間距假裝持有期或標籤期限。

| 項目 | 下一輪必須選定並保存的內容 |
| --- | --- |
| 觀察單位 | 先決定一筆是整個組合的決策事件、單標的標籤事件，或每日績效。這三者不可互換。若跨標的共用 RPS 排名或組合資金，同一決策時點的相關列須一起分組。 |
| `sample_id / event_id` | 穩定識別、所屬決策時點、標的／組合範圍，以及與 batch、候選、split 的關聯。 |
| 特徵資訊 | `feature_start`、`feature_end`、`known_at`、所用 bars／特徵資料指紋；指標暖機區間及資料可用時間須分開。資料日期不等於當時可取得時間。 |
| 目標／報酬資訊 | `label_start`、`label_end`、完整標籤或報酬的可知時間、價格基礎、費用與缺值。未平倉或未知終點保留未知，不能當成當天結束。 |
| 持倉狀態 | 訊號時點、最早可成交時點、實際模擬持有起訖、跨段現金／部位來源、退出或期末估值政策。每日 mark-to-market 仍可能依賴較早建立的部位。 |
| 歷史股票池 | 每個決策時點的成分與排序、納入／移除的有效時間與當時可知時間、退市／更名處理、完整 RPS 同儕集合。保存時的一份股票池不能冒充歷史成分。 |
| 資料版本 | 同一快照的原始資料、調整價修訂／公司行動處理、方法版本與日曆；若只有目前修訂日線，清楚標為該資料條件下的研究，不能聲稱 point-in-time 重建。 |

初始範圍建議限定日線、XNYS、既有收盤訊號／次日開盤口徑及明確有限期限的合成事件，避免同時引入日內成交、事件標籤與新供應商。這是計算與工程範圍的提案，不是足夠樣本數或可推論性的宣告。

## 5. Purging、embargo 與 split 的擬定契約

先以原時間順序將決策時點分組，不 shuffle；共同決策時點不能跨 train/test。對每個 split，保存原始 train/test 樣本 IDs、被排除 IDs、逐項原因與最後樣本 IDs，不能只輸出最後剩餘筆數。

**區間端點提案**：所有資訊支撐區間使用閉區間，端點相同也算重疊。這是便於驗收的保守定義，必須在實作前審定。train 標籤所需區間與任一 test 標籤區間相交時，排除 train 樣本並記 `label_overlap`；不能只檢查「訓練開始日在測試區間內」，以免漏掉完整包覆或尾端相交。

**Embargo 提案**：對每個測試區間，在其資訊終點之後留出預先宣告的 XNYS 交易日數 `E`，排除決策時間落入該尾隨區間的 train 樣本。`E` 的起算點、單位及納入端點須固定；`E=0` 只能在宣告中明示，不能以缺值代入。不得依哪個 E 的結果最好來回選擇而不新增候選。實際 E 尚待資料依賴與研究目的決定，本文不給一個看似通用的百分比。

特徵長回看、RPS 橫斷面計算與組合狀態還有額外資訊依賴。**本專案額外防護提案**：以 manifest 建立依賴檢查，若 train 特徵或初始持倉仍使用受隔離的 test 資訊，另標 `feature_dependency_overlap`／`state_dependency_overlap`；不得以已做標籤 purge 取代這項核對。資料邊界未知，該 split 不可用。這比單純比較標籤區間多了一層專案政策，需要合成反例驗收，不能聲稱 embargo 自動消除全部依賴。

切分後不足以估計宣告指標、沒有候選、零變異或算術非有限，保留不可用與原分母；不補值、不合併相鄰日期、不縮短 E 來湊有效結果。多個 split 及其重組路徑會重用資料，輸出不能假設它們是獨立樣本，也不能直接套用獨立 Bernoulli 樣本的信賴區間。

## 6. 每個 split 究竟執行什麼

未來 evaluator 必須先選定以下一種程序，並將選擇納入 declaration，不能在回應中混用：

1. **固定規則情境**：設定已事前固定，沒有訓練或設定選擇。只評估宣告情境，維持 descriptive 名稱。
2. **有限 deterministic 候選選擇**：每個 train 側在固定候選集合上計算宣告目標，按事前同分政策選取設定；test 側只套用所選設定。排名、權重、門檻或 allocator 超參數若經 train 選擇，全部屬於這個程序的輸出，不能使用整段歷史最佳設定。
3. **需要 fitting 的模型**：每個 split 各自 fit 特徵轉換、模型及必要校準；內部超參數選擇也限於 train 內的預先宣告流程。test 標籤只供最後評分。scikit-learn 官方說明同樣要求前處理僅從訓練資料學得，測試資料不得參與模型選擇。[官方資料洩漏說明](https://scikit-learn.org/stable/common_pitfalls.html#data-leakage)。本草案未選定或新增任何模型依賴。

每次輸出至少保留 `split_id`、完整候選分數／不可用原因、選取規則與同分集合、訓練樣本指紋、擬合／所選設定指紋，以及每個 test 事件的預測或決策證據。測試期資料變化可以改變 test 評分，但不能回頭改寫已固定的 train 選擇。

**組合路徑不能只拼接 NAV 列。** 每段 test 決策的來源 fit、期初部位、資金約束、費用與狀態接續都必須有明確的 replay 規則。若用不同 split 訓練的策略拼接兩段，是否平倉、如何承接部位、是否重新配置及誰負擔邊界成本，都會改變結果。首個合成階段只驗證事件輸出覆蓋，不產生「組合 CPCV NAV」；待此狀態契約選定後，才以事件重播建立路徑。現有 v1 的無終端清倉與跨段持有不能偷偷改成零持倉起步，也不能從完整原路徑借來測試期初狀態。

## 7. 分階段、有限範圍的下一輪提案

以下各階段都需下一輪明確選定範圍；本文不啟動實作。

| 階段 | 可交付的有限成果 | 怎麼證明它有效／停止條件 |
| --- | --- | --- |
| A：研究宣告與時間 manifest | 與 registry 共用身分；選定 estimand、觀察單位、區間端點、資料可知時間、E 與候選／attempt 規則。 | 所有必要欄位有來源；未定義欄位列為 blocker。不能以未知值產生統計結果。 |
| B：純合成 splitter | 第一個候選規格固定四個時間組、每次兩組 test，列完六種組合；2–4 個宣告候選、至多 252 個合成決策時點；完整保留 purge／embargo 證據。這些是測試執行上限。 | 六組完整且無重複；每一時間組被測試三次（由組合列舉可直接驗算）。逐樣本排除與以下反例吻合。沒有產品 API、資料庫寫入或 NAV 績效宣稱。 |
| C：受控的 split evaluator | 先選「有限 deterministic 候選選擇」或模型 fitting 之一。首輪最多 4×6 次候選／split 計算；固定 seed 清單或明示無隨機性；完整測試輸出可追溯。 | 只改 test 標籤時 train artifact 不變；所有宣告候選／切分都有結果或原因。計算超限就拒絕完整工作，不截短。組合狀態契約未完成前不重組 NAV。 |
| D：條件完整的本機實驗 | 對已登錄 batch 做明確本機執行，逐項核對歷史股票池、資料版本、事件覆蓋及狀態重播。另行審閱 batch 範圍的 CSCV／PBO 估計定義。 | 實測前先固定有限預算與完整輸出上限；缺 PIT 資料就保留相應主張不可用。任何 PBO 名稱只能對其完整且已宣告的選擇問題負責，不能擴張到未知的過去搜尋。 |

CSCV 的候選排名問題與 CPCV 的 train/test 路徑生成是兩條方法軸；D 不應將「跑完 CPCV」直接轉成「PBO 已完成」。若未來沿用現有同分延伸，必須仍分列嚴格低於、恰等於、低於或等於中位數；若更改排名或權重，需新方法版本與新的手算驗收。沒有任何比例門檻會在本草案中改變提案或交易資格。

## 8. 五組合成驗收與反例

以下是**未來測試規格，尚未執行**。只使用合成 IDs、時間索引與數值，SQLite 測試若日後需要則固定 `PANEL_DB_PATH=tmp_path`；不需私人持股或新資料供應商。

- **研究目的**：先驗證固定設定、有限候選選擇，還是可擬合模型？要的是 CPCV 情境分布，還是時間向前的部署模擬？是否保留不回看的最後時段，需另定用途與規則。
