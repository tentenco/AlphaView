# 比較兩份保存的執行研究

方法版本：`alphaview-execution-study-receipt-comparison-v1`。

在「執行研究回條」讀取歷史後，可從已載入、可驗證的回條中選擇基準與對照，再明確按「比較兩份研究」。比較限定同一帳戶、同一保存提案、同一研究種類；不重跑成交量 DAY、開盤限價 DAY 或多日 GTD，也不讀取行情、送出委託或保存另一份研究。

差額方向一律是「對照 − 基準」。參與率與逐標的限價是允許不同、且會並列顯示的情境假設。比較不是挑選較佳參數，也不宣稱變更造成實際成交或績效差異。沒有總股數、總金額、勝負、排名或比較通過標籤。

## 什麼情況可列差額

以下基礎必須完整且一致，否則**所有差額為 null**，保留各自原值、不可相容原因與兩份完整原始回條：

- 已理解的方法版本：回條 v1，以及對應成交量／限價／GTD v1 與 paper-v2；相同但未知的版本也不能視為可比。保存的方法說明須一致。
- 同一完整保存提案紀錄指紋與提案指紋；固定訂單順序、標的、方向、股數、參考價、股數精度及原始來源識別一致。
- 同一研究計算時的輸入 revision、完成交易日與帳戶版本／政策上下文。
- DAY 必須是同一確切交易日；GTD 必須是同一完整到期日、逐日 horizon 及交易日完成狀態。不同日期不取交集、不對齊成較短期間。
- 原始日線證據指紋、逐筆／逐日證據覆蓋與訂單／日期識別一致。保存的股數、日期、狀態及覆蓋結構也須可核對。

GTD 參與率提高後，若較早用完情境股數，後續日期會標為不再需要證據；這可能使原始資料指紋或覆蓋不同，因而不能列差額。這是刻意保留完整基礎的限制，不把兩份資料截短或補齊。相同未來未知期間仍可比較已知前段；最終股數與到期量維持未知。

基礎相符時，只對確切標的與日期的兩個有限、已知數值計算差額。缺欄位、缺訂單、缺日期、null、不可用或非有限值保留 null 與原因；明確的零情境才顯示零。DAY 包含開盤價、全日量、容量、情境股數、到期股數、情境比例與參考金額。GTD 分開列出已觀察前段、最後已知剩餘、最終值及逐日容量／情境／剩餘量，沒有把未知尾段混入總數。

差額使用保存數字表示的 Decimal 相減，80 位計算精度後回傳有限 JSON 數字；比例差額單位為百分點，股數為 shares、參考金額為 USD、價格為 USD/share。保存的原始 exact 小數字串仍完整保留在原回條，沒有改寫。

## 歷史性與原始下載

當前性是比較讀取時的獨立觀察。兩份相同舊快照的合法回條，即使行情、最新交易日或帳戶目前已改變，仍可比較保存值。API 另外要求目前帳戶版本與呼叫者的 `expected_account_version` 相符；這個 409 檢查不讓舊回條取得新的執行資格。

回應中的 `baseline.original_receipt`、`selected.original_receipt` 直接嵌入資料庫保存的完整 JSON 位元組，而非 parse/stringify 重建。兩邊的完整回條指紋、原始研究 JSON 指紋、原始狀態與當前性分開保留。完整比較下載使用已接受的原始回應字串，包含兩份原回條，不會再發 POST 或產生新研究。HTTP ETag 是完整比較回應的 SHA-256；瀏覽器接受回應前會核對完整位元組指紋及帳戶、提案、兩個回條識別與預期指紋。

## API 與元件

`POST /api/paper/accounts/{account_id}/proposals/{proposal_id}/study-receipts/compare`

```json
{
  "baseline_receipt_id": "64 位小寫十六進位",
  "selected_receipt_id": "另一個 64 位小寫十六進位",
  "expected_baseline_fingerprint": "基準完整回條指紋",
  "expected_selected_fingerprint": "對照完整回條指紋",
  "expected_account_version": 1
}
```

請求禁止額外欄位、非有限值、bool 版本、重複回條與超界版本。帳戶／提案 ID 必須為 32 位小寫十六進位。跨帳戶／提案是 404；變更指紋、帳戶版本、損壞回條或觀察交易日中途變更是 409；跨種類與超過 5 MiB 的完整回應拒絕，不截短。唯讀端點使用 `@store.snapshot_read`，只讀回條與目前來源 metadata，沒有新增 schema、匯入、刪除或持久化。

`ExecutionStudyReceiptComparison` 接受 `accountId/proposalId/accountVersion/kind/receipts/total/enabled/t`。父 `ExecutionStudyReceipts` 只把已載入的歷史清單傳入，不另做自動讀取。選單涵蓋本次已載入歷程中的全部可驗證回條，不受歷程搜尋或前端分頁影響；畫面明示已載入數量／總量，不聲稱涵蓋尚未讀取的歷史。帳戶／提案／種類切換重置選擇，版本、清單、選擇、enabled、pagehide 與 unmount 變更會中止待處理請求並清除舊比較／下載。父層研究草稿不受影響。

## 大量訂單的檢閱

已接受比較中的訂單清單每頁最多 25 筆，可用股票代碼做不分大小寫的字面子字串搜尋。畫面顯示符合搜尋／原比較全部訂單筆數、目前範圍及頁次；搜尋零筆時明示空清單與停用的分頁按鈕。維持伺服器原順序與原始陣列位置，不排序、不合併、不重新命名股票代碼。

每筆使用預設收合的原生 `details`／`summary`。摘要保留股票代碼、原始基準／對照狀態，以及下列**訂單層級差額欄位**計數：

- 欄位總數：只數該訂單原有的 `metrics`。
- 已知非零差額欄位：差額為有限數字且不等於零；已知零與負零不計入。
- 未知差額欄位：差額為 `null`。比較基礎不相容時，所有差額仍為未知。

逐日 `sessions[].metrics` 不加入摘要分母，仍在展開的原始逐日明細內呈現。這些欄位計數只協助瀏覽，不是股數或金額的合計、沒有變化的判定、完整性證明或研究結論；未知不能被當成零，也不產生贏家或排名。展開後保留原始數值、單位、缺值理由與逐日資料。

完整可比性結論及原因、兩邊回條的原始狀態／當前性／假設與指紋、完整比較基礎，以及完整原始 JSON 下載，全部保留在搜尋與分頁範圍之外。即使只顯示一筆或零筆，整份不相容結論也不會消失。下載仍是原先接受的完整伺服器文字，包含全部訂單及兩份原件，不依搜尋重組檔案。

搜尋變動回到第一頁；新接受的比較回應重設搜尋與分頁。相同比較的無關重繪不清掉搜尋、頁次或仍在頁面上的展開狀態。原有來源失效、請求取消、409、回應解析與下載生命週期維持原樣。清單操作不發請求、不寫 storage／hash，也不動父層草稿；多個比較元件各自使用獨立控制識別。

原生搜尋、按鈕與摘要可用鍵盤聚焦；搜尋欄 Enter 不會觸發外層表單送出。390px 寬時控制改為直向，摘要與狀態允許換行。這次只調整檢閱呈現，不變更比較方法 v1、後端或執行權限。

介面合成驗證包含 100 筆原順序與 25 筆分頁、零／非零／未知欄位及逐日分母隔離、搜尋無結果、無關重繪保留、新回應重設、兩個元件互不影響、未送出草稿、原始 JSON 位元組一致，以及原有空選擇、連點、來源切換、409 與晚到回應案例。真瀏覽器與 390px 整體驗收由本輪主代理在整合後執行。

## 完整訂單與逐日比較 CSV

「下載全部訂單與逐日比較 CSV」以已接受並核對的完整回應匯出長格式資料。每個 `orders[].metrics` 指標一列，每個 `orders[].sessions[].metrics` 指標也各一列；不使用搜尋後的清單或目前頁面。DAY v1 每筆訂單有 7 個指標；GTD v1 每筆訂單有 6 個摘要指標、每個保存日期有 7 個指標。例如 100 筆各有 5 個保存日期的 GTD 比較，CSV 共 4,100 列。額外保存的指標也逐項保留，不截短或略過。

每列包含下列資訊：

- `record_level`（`order`／`session`）、原始 `order_number` 與股票代碼、原始逐日序號、日期及 `date_present`。訂單摘要涵蓋整段研究，本身沒有單一日期，日期欄為空白且 `date_present=false`；逐日列直接使用保存日期。
- 原始配對旗標、兩邊狀態及其是否已提供、兩邊理由、指標名稱與單位、基準／對照原值、保存差額與理由。三個數值各有 `*_present` 與 `*_state`（`present`／`unavailable`）；真正零值保留 `0`，未知的實際 `null` 是空白且明示不可用，不補零。有限值與正負號保留數值精度，不以畫面格式重建。
- 兩份完整回條識別與指紋、原始研究 JSON 指紋、帳戶／提案識別、方法版本與原方法說明、研究種類、`checked_as_of` 與 input revision、讀取時的來源當前性及原因。未知 currentness 為空白。
- 整份 `full_basis_compatible` 與不相容原因、`selected_minus_baseline` 差額方向，以及固定 `execution_authority=false`。相容性是整份比較的既有結論，不是依當前搜尋或個別指標重新推斷。

基礎不相容時，CSV 保留每邊的有限原值，全部差額必須仍為原始 `null`，並附 `comparison_basis_incompatible`。基礎相符但指標缺值時，保留原本的缺值理由。必要來源、完整 v1 基礎檢查、指標、狀態／理由欄或逐日結構缺漏，以及任何非有限值，均拒絕整份 CSV，顯示原因並保留完整原始 JSON 下載；不另算差額、不忽略問題列。

CSV 使用 UTF-8 BOM、CRLF 及 RFC 4180 引號轉義。所有文字欄位，包括方法、來源 metadata、股票代碼、指標／單位及理由，都有試算表公式注入防護；有限數值本身維持數字表示。這是便於閱讀的副本，不是 canonical 證據、實際成交或交易授權。兩份原回條、原始 exact 字串與完整比較仍在逐字保留的 JSON 下載內。

CSV 僅在明確點擊時本機下載，不發新請求、不重跑研究、不寫資料。帳戶、提案、版本、種類、來源清單、選擇、enabled 或 pagehide 改變時，沿用既有結果失效規則，舊 CSV 按鈕不能繼續使用。下載 URL 沿用原有清理生命週期。

合成測試涵蓋 DAY 100 筆／700 列、GTD 100 筆／4,100 列、已搜尋或翻頁仍匯出全部內容、缺值與不相容標記、已知零／負數／精度、公式與引號換行防護、結構或非有限值整份拒絕、來源切換失效，以及 CSV 下載後原始 JSON 位元組仍相同。

## 這不是什麼

這不是實際成交、開盤流動性、限價日內先後、券商核對、因果歸因、獲利預測或交易授權。全日量仍是事後容量代理；不可用或未來未知的原研究仍然不可用。完整性與可比基礎相符，均不代表研究假設能在真實市場執行。
