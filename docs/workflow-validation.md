# 保存工作流的單項規則驗證

版本：`alphaview-workflow-validation-v1`。入口在 Agent 投資組合的保存工作流明細與紙上提案之間；必須先取得當期可用的保存工作流，再按「檢查選定標的的啟用規則」。計算只用本機日線，不呼叫模型、資料供應商或券商。

## 檢查範圍

每次選 1–5 檔**該保存工作流實際選入**的標的。每檔套用該工作流所有權重大於零的規則：

| 保存規則 | 使用的既有 Research Desk 規則 | 限制 |
| --- | --- | --- |
| turtle | `alphaview_turtle`，固定參數 | 同一套海龜進場與低點出場規則 |
| trend | `alphaview_trend`，固定參數 | 同一套趨勢進場與均線出場規則 |
| pullback | `alphaview_pullback`，固定參數 | 同一套回檔進場與 RSI／均線出場規則 |
| rps | 無 | 跨標的排名沒有等價的單一標的模擬，回報 `unsupported_cross_sectional_rule`，仍計入所需覆蓋分母 |

沿用 `alphaview-validation-v1` 的分段一致性、bootstrap 區間與 PSR／DSR。這些是各規則獨立的檢定，不計算加權平均績效或組合結論，也不把某規則的缺口挪給別條規則。回傳 `pass`／`warn`／`fail` 只屬於那一個標的與規則。

固定測試區間是最新 **252 個完成 XNYS 交易日**，4 段，區間之前的本機歷史只供指標暖機。起始現金 100,000、單條規則部位 100%、費用 10 bps、滑價 0 bps，沒有額外停損／停利；前日收盤訊號、次日開盤成交。這個 100% 是單條規則的獨立模擬設定，不是保存工作流的配置權重。介面在執行前顯示這些設定，回應也帶完整 `request.risk`。

若暖機導致實際測試起日較晚，各列顯示實際起迄日與交易日數；檢定樣本不足就保留不可用原因，不填成 0。`trials` 由使用者申報比較過的設定數（1–500），不會執行最佳化或新增參數搜尋。

## 有限計算與完整覆蓋

- 每次至多 5 檔、15 次有映射規則的驗證，逐一執行。每檔原始本機日線至多 3000 筆；超過時在載入 `Series` 前就標為不可用，不偷偷截短歷史。缺當期日線不使用舊價格替代。
- 覆蓋分母是**整筆保存工作流的選入標的數 × 啟用規則數**，包含 RPS。回傳另列本次要求、已計算、全部檢定可用、整列不可用與未檢查的組數。
- 若只挑部分標的，介面明示部分覆蓋與未檢查清單。已計算列若 bootstrap 等檢定不可用，仍列出缺口；「已計算」不等於通過或全部證據齊備。

## API 與來源綁定

`POST /api/portfolio-agent/runs/{identifier}/validation`，唯讀、`snapshot_read`、`Cache-Control: no-store`。輸入：`symbols`、`trials`、`expected_proposal_fingerprint`、`expected_input_revision`、`expected_as_of`。額外欄位、重複／未選入代碼、布林或非整數 trials、超出範圍均拒絕；來源／指紋不一致回 409。

回應包含 workflow／validation／Research Desk 方法版本、run ID、保存提案指紋、保存規則指紋、驗證證據指紋、行情 revision、交易日、固定請求設定、每列原始歷史指紋與實際測試區間。保存規則指紋涵蓋保存提案指紋、啟用權重、固定映射與方法版本；證據指紋再綁測試請求及 revision。

`current_at_snapshot` 只表示計算快照的來源有效，不宣稱回應之後仍當期。所有規則共用同一讀取快照；UI 收到結果後重新讀取該筆 run 的當期狀態，之後每 30 秒或回到分頁時只重查本機來源。來源變更、讀取失敗或帳戶／工作流切換，都不繼續顯示為可用證據。新計算仍須按鈕觸發；重複點擊受保護，離開時中止等待。

## 這不是什麼

- 不是加權共識、配置器或整個投資組合的回測與驗證；沒有總體 `pass` 或組合報酬。
- 不是提案閘門。此版本只有 `advisory_only`，不提供 `require_pass`，不把暫時畫面上的結果當作保存提案的證據。
- 不改配置、不重分配缺失權重、不保存新研究紀錄、不建立紙上提案、不送單。既有提案驗算與來源檢查照常運作。
- 檢定通過不能保證未來有效；資料修訂、倖存者偏差與未申報的搜尋次數仍是限制。

實作：`alphaview/panel/workflow_validation.py`、`web/src/WorkflowValidation.tsx`。測試使用隔離 SQLite 與合成日線，並禁止外部 HTTP。

## 離線驗證 JSON

完成驗證且來源仍有效時，可按「下載目前驗證 JSON」。檔案保存這次伺服器回應的完整物件：所有方法版本、run／提案／規則／歷史／證據指紋、交易日、input revision、固定請求與風險設定、覆蓋計數、逐規則理由及限制。保留已接受回應的原始 JSON 文字，不重新序列化，因此 `1.0`、`-0.0`、指數表示法、Unicode 跳脫與未知擴充欄位也保持原樣。接收與下載時會確認解析後的完整物件與原文一致、所有數字有限；不新增總體結論或重算數值，`null` 缺值仍為 `null`。非有限數值會拒絕接收或下載，不偷偷轉成缺值。

下載不發出新請求、不重新執行驗證、不改提案。更換標的或 trials、重新計算、工作流／帳戶切換或來源失效後，原下載入口消失，原始文字與結果一併清除；即使回到先前設定或生命週期恢復，也須重新檢查。來源重新檢查期間停用。檔名只使用安全化、限長的日期與 run ID，下載後清除臨時連結並釋放 Blob URL。

離線檔案只保存當次證據；`current_at_snapshot` 不是開啟檔案當下的新鮮度保證，也不把單項規則的結果變成整體配置通過驗證。
