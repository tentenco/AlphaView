# 保存工作流的固定四段路徑

方法版本：`alphaview-workflow-path-segments-v1`。唯讀拆解既有 `alphaview-workflow-path-validation-v1` 的同一條 252 交易日路徑，顯示報酬、回撤與交易活動是否集中於特定期間。沒有 SQLite schema 或計算引擎既有版本變更。

## 固定時間邊界

伺服器在單一 `@store.snapshot_read` 快照內只呼叫原路徑 `evaluate` 一次，完整回應原封保留在 `baseline`。不額外載入行情，不對各段重新選股、配置、訓練或最佳化，也不重設現金及部位。

以 `V₀` 表示原路徑的初始資金，日期為 `baseline.window.signal_start` 的前置收盤邊界；`Vᵢ` 是第 i 個估值交易日的未調整收盤 NAV。原路徑已有 252 個估值收盤，因此固定切成：

| 段 | 期初邊界 | 本段估值收盤 | 期末 |
| --- | --- | --- | --- |
| 1 | V₀：前置收盤日期上的初始資金 | 1–63 | V₆₃ |
| 2 | V₆₃：上一段期末收盤 | 64–126 | V₁₂₆ |
| 3 | V₁₂₆：上一段期末收盤 | 127–189 | V₁₈₉ |
| 4 | V₁₈₉：上一段期末收盤 | 190–252 | V₂₅₂ |

每段輸出 `boundary_date`、`start`、`end`、全路徑交易日序號及 `boundary_source`。本段第一個交易日的開盤成交及費用屬於本段，上一段最後交易日的成交屬於上一段。訊號日在邊界收盤、成交日在本段第一日的決策也歸本段。日期皆沿用已完成 XNYS 交易日曆，沒有曆日替代或重疊。

## 指標公式與符號

第 j 段期初 `Bⱼ = V[63(j−1)]`，期末 `Eⱼ = V[63j]`。所有指標使用原路徑的浮點計算精度；只有畫面顯示才四捨五入。

- **報酬（%）**：`rⱼ = 100 × (Eⱼ / Bⱼ − 1)`。四段須連乘：`∏(1 + rⱼ/100) = V₂₅₂ / V₀`，不能直接相加。
- **資產增減**：`Δⱼ = Eⱼ − Bⱼ`。四段可相加，`ΣΔⱼ = V₂₅₂ − V₀`。包含價格、原路徑成交及費用的綜合結果，沒有額外終端清倉。
- **最大回撤（%）**：依時間追蹤最高值，初值為本段 `Bⱼ`；取所有本段收盤 `100 × (Vₜ / max(Bⱼ, 本段首日至 t 的 NAV) − 1)` 與 0 的最小值。結果為**負值或零**，包含第一日相對邊界的損失。各段最高點重置只用於分段回撤統計；實際模擬資金與持倉不重置。分段回撤不能相加，也不等於完整路徑最大回撤。
- **成交明細筆數**：本段 `trade_date` 的原始事件內，所有個別買／賣明細筆數。一次換股的買與賣分別計數；沒有成交則為已知的 0。
- **模擬費用**：加總本段原始事件的 `fee`，核對其與各筆交易費用合計一致。沒有重新推算費率、滑價或稅金。
- **成交金額**：加總本段各筆原始交易的非負 `notional`，買賣都計入。
- **雙邊周轉率（%）**：`100 × traded_notional / boundary_value`。分母是本段期初 NAV，**不除以二、不年化**，不是以平均資產為分母的基金周轉率。

`reconciliation` 保留連乘報酬與全路徑報酬、其百分點差額、加總資產增減，以及費用／成交金額／筆數核對差額。浮點連乘核對使用 `1e-10` 相對及絕對容差；這是數值一致性檢查，沒有統計通過結論。費用、金額及筆數可按段加總；周轉率因各段分母不同而不相加。

每段 `normalized_curve` 包含期初邊界（session 0，指數 100）與 63 個估值收盤，共 64 點。其值為 `100 × NAV / boundary_value`；畫面四張圖採共同尺度。這只是顯示單位的換算，不建立新帳戶或重設本金。`curve_indices` 為完整原路徑的零起始半開區間；`decision_indices` 與 `event_indices` 指向未修改的 `baseline` 證據。

## 缺值與來源

原路徑不可用時，仍回傳四個各自要求 63 日的期間，`metrics: null`、空衍生曲線、`covered_sessions: 0` 與完整原因。若日期可得，保留固定的目標日期、已知決策／事件數；`observed_sessions` 僅計原路徑中落於該段的不同日期。無法建立完整日曆時，日期保留 `null`，不猜測交易日。

原路徑的 252 日期、邊界值、事件日期或費用／成交彙總不一致，同樣使四段衍生指標全數不可用；不留下部分成功的段落。非有限來源不能形成 JSON 證據，回 422；分段運算溢位則四段保留空值。缺值在畫面為 `—`；已知 0 報酬、0 回撤、0 費用及 0 筆成交仍顯示 0。

證據包含原路徑、原路徑指紋、歷史與設定指紋、固定分段方法指紋及完整回應 SHA-256。保存工作流的預期來源不符回 409；完成拆解後再次核對已完成交易日。沒有行情抓取、模型或券商呼叫，也沒有提案、帳戶、帳本或收據寫入。

## API 與介面

`POST /api/portfolio-agent/runs/{identifier}/path-segments`，嚴格 body 與原路徑相同：

```json
{
  "expected_proposal_fingerprint": "64 位小寫 SHA-256",
  "expected_input_revision": "目前保存輸入版本",
  "expected_as_of": "YYYY-MM-DD"
}
```

分段數與長度固定，額外 `segments`、日期或最佳化參數均拒絕。回應 `Cache-Control: no-store`；來源有效只代表當次快照，不代表離線開啟時仍當期。

`WorkflowPathSegments` 接受 `run`、`enabled`、`t`。明確按鈕才計算；完成後重新讀取工作流，之後每 30 秒及回到分頁時重新核對來源。連點只送一個請求；工作流、帳戶政策關聯、可用狀態或頁面生命週期變更會清除已接受證據。等待替換結果或來源核對時不能下載舊結果。

下載保存已接受回應的完整原始 JSON 文字，保留 `1.0`、`-0.0`、指數寫法、未知欄位與 `null`，沒有額外 API 或前端重算。下載前核對原文與接受物件的完整語意及有限數值；不因 JavaScript 重新序列化而改變後端指紋重算口徑。

## 這不是什麼

這是同一條連續且帶事後偏差軌跡的時間拆解，**不是四個獨立 fold、walk-forward、CPCV、PBO、樣本外驗證、策略穩健性證明或交易指示**。固定候選、保存設定、目前修訂調整價、原路徑缺失的風控與成交限制均維持。沒有 Sharpe、最佳段排名、統計 pass/fail 或配置建議。
