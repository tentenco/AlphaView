# 密集歷史前綴覆蓋

`alphaview-research-prefix-coverage-v1` 是手動、唯讀的 Research Desk 診斷。使用者選定一個標的、一組既有策略設定，以及明確的訊號開始／結束日期，程式逐一重建每個合格歷史前綴。既有 `alphaview-research-integrity-v1` 的最多六切點抽樣功能與保存回條維持獨立，不會改成密集計算。

## 比較範圍與計算

完整歷史結束於請求的 `test_end` 與 `sessions.latest_completed_session()` 較早者。使用真正的 `research_desk.Series`、`signals` 與策略指標，保留本機歷史原始起點以供暖機；不把資料裁到 `test_start` 才開始算 RSI。起始比較日期是完整歷史第一個有效訊號日期與 `test_start` 所指定日期的較晚者。這之後若出現無效訊號或非有限指標，會計入缺口，不再略過。

令選定訊號日期數為 `N`，每個前綴至少包含 20 個比較日期，且完整歷史中至少有一筆較晚資料。因此所需切點數為 `max(N − 20, 0)`，切點涵蓋第一個比較日期起算第 20 筆至完整歷史倒數第 2 筆，沒有等距抽樣。20 日期沒有合格切點；21 日期有一個。日期依本機驗證後的 Series 排序，以實際日期回傳首尾切點。

每個切點都從原始歷史起點重新建立獨立 Series 與訊號，包含 Wilder RSI 的遞迴種子；不沿用完整 Series 切片當成重建結果。只比較選定訊號區間中、截至該切點的值。比較涵蓋 entry／exit／valid、調整收盤，以及各策略實際依賴的 SMA、前一日 SMA、RSI、通道高低點、母體標準差、量比、前收與相關均線；前一日 SMA 是本方法增加的觀察欄位，沒有更改原抽樣 v1。布林值精確比較，數值使用 `rtol=1e-10`、`atol=1e-12`。

成本有兩道上限：

- **2,000 筆本機日線**：計入該標的所有保存日線，建立任何 Series 前即檢查；超過時 `required_cutoffs` 為 `null`，因為尚未得到暖機與訊號區間。
- **120 個合格切點**：完整 Series 算出所需數量後，先檢查再建立前綴。剛好 120 個會全部重建；121 個就回傳 `cutoff_limit`、精確所需數量與上限，沒有前綴計算、切點抽樣或悄悄截短。

最多建立完整 Series 一次與前綴 120 次。差異及缺值明細各至多 100 筆，完整計數及截斷旗標保留。切點清單在上限內完整列出所有要求的切點、個別歷史指紋及比較／不可用狀態；某個前綴重建失敗仍保留那一列與原因，不把其他切點當成已覆蓋它。超過上限時不產生清單，`manifest_complete=false` 且明示未計算；可以由首尾與精確數量看出要求的範圍。

## API 與回應

`POST /api/research-desk/prefix-coverage` 使用 `@store.snapshot_read`，回應 `Cache-Control: no-store`。沒有資料庫寫入、行情更新、模型或券商呼叫。

```json
{
  "symbol": "SYNTA",
  "config": {"strategy": "sma_cross", "params": {"fast": 5, "slow": 20}},
  "test_start": "2024-01-02",
  "test_end": "2024-02-29",
  "expected_input_revision": "synthetic:1",
  "expected_as_of": "2024-12-31"
}
```

標的與策略沿用既有嚴格驗證；日期不得為空、無效或倒序，未知欄位及 `max_prefixes` 一律拒絕。非有限參數與布林數字不被接受。來源 revision 或完成交易日與目前快照不符時先回 409，不開始計算。

回應包含完整固定請求、三種方法版本、快照交易日與 revision、完整歷史指紋、逐切點來源指紋、實際視窗／暖機起點、完整切點清單、比較統計、明細、不可用原因及對整個回應計算的 `evidence_fingerprint`。`current_at_snapshot` 只說明當次快照；它不保證下載或打開檔案時來源仍相同。

`coverage.required_cutoffs` 無法計算時保留 `null`；已確定沒有合格切點才回零。`attempted_cutoffs`、`compared_cutoffs`、`failed_cutoffs` 分開呈現。`cutoff_coverage_complete` 表示所有要求切點均完成比較；`complete` 另要求沒有必要值或訊號缺口。完整覆蓋可以發現差異，所以不是策略通過驗證。差異與缺值可同時存在；`differences_found` 保留已觀察到的差異，並仍顯示不完整覆蓋與缺口。`no_difference_detected` 只會出現在完整覆蓋且沒有差異的情況。

比較日期會在不同切點重複出現，`compared_session_pairs` 是比較次數，不能當成獨立統計樣本數。

## 縮小範圍與下載

伺服器在可推導時回傳 `suggested_window`：保留至相同有效結束日的最後最多 100 個暖機後訊號日期，起訖為實際 Series 日期。按「使用最後最多 100 個訊號日期（不執行）」只填入兩個明確日期、清除原結果；不會自動呼叫端點，使用者仍須再次按比較。這個選項可能改變原本選定區間，所以日期完整顯示，不靜默取代請求。

畫面需要 `symbol/config/testStart?/testEnd?/inputRevision/asOf/contextIdentity?/enabled?/t`。父層把帳戶／研究紀錄／草稿身份放入 `contextIdentity`，忙碌時傳 `enabled=false`。標的、設定、日期、來源、父層身份或生命週期變更會中止等待並永久清除當前證據；晚到回應不能恢復，回到舊設定也不自動恢復。連點只發一個請求。取消瀏覽器等待不保證停止伺服器已開始的同步計算，因此後端成本上限仍獨立適用。

下載使用已接受回應的原始 JSON 文字，保留浮點表示法、負零、指數、Unicode、完整未知欄位與 `null`；先確認完整解析物件吻合原文、所有數字有限。下載不新增請求、保存回條或資料庫寫入，檔名安全化，臨時連結及 Blob URL 會釋放。

## 這不是什麼

這是**目前保存資料、固定設定、明確日期區間的合格切點**之全數比較，不是所有可能未來資料洩漏的證明。少於 20 個比較日期的切點、其他窗口／設定／標的、歷史資料修訂與當時可取得性、倖存者偏差、跨標的選樣、績效與成交模型皆不在範圍。不計算配置、不重新分配權重、不改保存提案、不授權任何交易。

測試使用隔離合成 SQLite，驗證全部既有策略、遞迴 RSI 從原始種子逐次重建、刻意未來洩漏、非有限缺口、120／121 邊界、日期與來源衝突、完整資料庫唯讀；UI 驗證按需執行、空日期、連點、中止、來源失效、精確原文下載及最後 100 日期的明示操作。
