# 保存提案的執行情境研究區

保存提案的日成交量容量、DAY 開盤限價與 GTD 多日開盤研究，共用一個預設收合的「執行情境研究（唯讀）」區塊。提案審閱與接受／拒絕控制留在研究區外；研究是選用資訊，不是接受提案前必須完成的步驟。

展開後，三個研究工具各有獨立的原生 disclosure，初始皆展開。區塊捷徑可以直接前往指定工具；「全部展開／全部收合」只操作這個提案內的三個工具，不會收合外層研究區，也不會更動其他提案或工作區。鍵盤可用 Tab 移動到摘要與導覽按鈕，使用原生 Enter／Space 操作；捷徑將焦點移到目標標題，尊重減少動態效果設定。窄螢幕的捷徑改成單欄，文字與按鈕可換行。

## 草稿與來源有效性

收合只影響顯示。三個研究元件與各自的歷史回條保持掛載，參與率、限價、GTD 日期草稿及工具展開選擇不會因收合而消失。收合不取消已由使用者啟動的請求，也不自動讀取來源、計算研究或保存回條。

同一帳戶與同一提案的來源版本、輸入 revision、交易日、提案 metadata 或可用狀態更新時，研究區保留原有 DOM 與草稿。所有來源與 `enabled` 參數原樣傳給各研究元件；原有的過期結果清除、請求中止、409 核對及頁面生命週期規則仍由各工具執行。切換帳戶或提案，則建立新的研究區，回到外層收合與初始草稿。開合狀態不寫入 localStorage、sessionStorage 或網址。

## 這不是什麼

這個區塊不是執行模型、交易授權或提案就緒閘，也不新增或改變研究算式、方法版本與後端端點。開啟、收合或閱讀研究都不改變提案接受資格，不寫入委託、帳本或券商帳戶。各情境的資料限制仍見 [日成交量容量研究](execution-volume-study.md)、[DAY 開盤限價研究](execution-limit-study.md) 與 [GTD 多日開盤研究](execution-gtd-study.md)。

## 驗證

`ExecutionStudyWorkspace.test.tsx` 使用三個實際研究元件，覆蓋初始收合與完整來源參數傳遞、反覆收合的草稿節點保留、來源更新與帳戶／提案切換、跨工作區導覽隔離與鍵盤焦點，以及收合不中止請求而來源變動仍會中止。另執行三個既有研究元件與共用 disclosure／導覽測試。
